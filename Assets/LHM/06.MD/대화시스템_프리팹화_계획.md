## 1. 요약

**바깥 프리팹 1개 + 손으로 다듬는 Canvas 중첩 프리팹 + 씬 연결 컴포넌트 1개**로 만든다.

| 지금 | 프리팹화 후 |
|---|---|
| DialogueTest에서 루트 13개를 복사하고 참조를 다시 잇는다 | 프리팹을 놓고 `씬 연결` 버튼을 누른다 |
| UI를 고치면 고물상 맵을 지우고 다시 배치한다 | 프리팹을 고치면 모든 씬에 반영된다 |
| 씬 구성 메뉴가 항목별로 많다 | 씬 구성은 `프리팹 배치`, `씬 연결` 2개 |

## 2. 구조

```text
DialogueSystem.prefab
 ├ DialogueSceneBinder     ← 씬마다 다른 값은 여기에만 둔다
 ├ Core                    매니저, 이벤트 큐, 보스 진입, 입력, UI 스택, 연출
 ├ TalkCamera              클로즈업 카메라
 ├ DialogueCanvas.prefab   대화창, 백로그, 말풍선 틀
 ├ BossRaceCanvas.prefab
 ├ DifficultyCanvas.prefab
 └ SeasonCallCanvas.prefab

DialogueSystem_Test.prefab (Variant)   테스트 키, 캡슐 NPC 등
NPC_Receptionist.prefab, NPC_JunkDealer.prefab   씬에 따로 배치
```

### 왜 이 구조인가

| 방식 | 판단 | 이유 |
|---|---|---|
| 루트 13개를 각각 프리팹화 | 채택 안 함 | 프리팹끼리 참조가 끊겨서 씬마다 다시 이어야 한다 |
| 통짜 프리팹 1개 | 채택 안 함 | 단순하지만 UI 수정과 시스템 수정이 한 파일에서 충돌한다 |
| **바깥 1개 + 중첩** | **채택** | 내부 참조가 유지되고, Canvas별로 나눠 작업할 수 있다 |

## 3. 씬 참조 처리

프리팹은 씬 오브젝트를 참조할 수 없다. 씬마다 다른 값을 `DialogueSceneBinder` 한 곳에 모으고, Binder가 실행 시작 때 각 컴포넌트에 전달한다.

| 씬에 있는 대상 | 지금 필드 |
|---|---|
| 플레이어 카메라 | `BubbleManager.worldCamera`, `PlayerInteractor.worldCamera`, `NpcTalkCamera.mainCamera`, `DialogueDirector.targetCamera` |
| 플레이어 | `NpcBubbles.player`, `FieldInputBridge.interactor`, `FieldInputBridge.movement` |
| LJS 시간 | `TimeSystemUiStack.timeSystem` (Binder 불필요, `TimeSystemManager.Instance` 사용) |
| 상점 창 | `NpcChoiceMenu.shopWindow` |
| 잠글 UI 단축키 | `FieldInputBridge.uiHotkeys` |
| 고철 수집 | `FieldInputBridge.interactions` |

- **`Camera.main`에 맡기지 않는다.** 고물상 맵의 실제 카메라는 `CAM_Stage`라서, 예전의 "말을 걸면 화면이 멈춘 것처럼 보이는" 문제가 재발한다.
- **실행 순서:** Binder는 `InputModeController`(`DefaultExecutionOrder(-100)`)보다 먼저 돌아야 한다.
- **채우는 방법:** 대화 툴의 `씬 연결` 버튼이 자동으로 찾아 채운다. 지금의 복사·재연결 코드를 대체한다.
- **빈 칸 처리:** 연결이 빠지면 NPC 대화와 카메라 연출이 깨지므로, 빈 칸이 있으면 시작할 때 에러를 띄운다.

## 4. 프리팹화 전에 풀어야 할 문제

### 4-1. 테스트 스크립트가 실제 기능을 맡고 있다

아래 기능이 테스트 스크립트를 거친다. 그냥 Test Variant로 빼면 실제 게임 흐름이 끊기므로, 이 역할부터 분리한다. 코드로 확인한 내용과 수정 방법은 9-1, 9-2에 있다.

| 기능 | 지금 담당 |
|---|---|
| 보스별 도전·패배 수, 진행 정보(`IBossRaceProgress`) | `Step09_DialogueDebug` |
| 00시 처리, 시즌 시작 전화 호출 | `Step112_MidnightTest` |

### 4-2. 씬별로 달라지는 설정

| 설정 | 처리 |
|---|---|
| Canvas 정렬 순서 | 프리팹에 충분히 큰 고정값을 넣는다 |
| 클로즈업 카메라의 URP 설정 | 켤 때 실제 카메라에서 복사하도록 런타임으로 옮긴다 |

### 4-3. DialogueTest의 값이 원본이다

손으로 다듬은 UI 위치·크기는 코드로 다시 만들면 사라진다. DialogueTest 씬의 현재 상태에서 프리팹을 뽑는다.

## 9. 보완·수정 목록

### 9-1. 프리팹과 별개로 먼저 고칠 문제

프리팹화 없이도 지금 존재하는 문제다. 테스트 스크립트를 Test Variant로 빼면 그대로 드러나므로 먼저 해결한다.

| 우선순위 | 문제 | 근거 | 영향 | 수정 |
|---|---|---|---|---|
| **높음** | 00시 처리가 개발 빌드 전용이다 | `Step112_MidnightTest.cs:20-98` 전체가 `#if UNITY_EDITOR \|\| DEVELOPMENT_BUILD` 안에 있고, `DaysPassed` 구독과 `EvaluateMidnight`, `SeasonRaceCall.Ring` 호출이 여기뿐이다 | 배포 빌드에서 00시 트리거, 서사 이벤트, 시즌 일차, 시즌 전화가 돌지 않는다. 전화가 없으면 `race.id`도 기본값에 머문다 | 새 `DialogueDayProcessor`로 옮긴다 |
| **높음** | 귀가 평가 호출이 테스트 코드에만 있다 | `queue.Evaluate("귀가")`가 `Step11_BossEntryTest.cs:135`, `Step15_BubbleTest.cs:43`의 `#if` 안에만 있다 | 실제 전투 복귀 후 패배 반응, 첫 패배 튜토리얼 T12가 나오지 않는다 | 전투 복귀 시점과 연결한다 (전투 담당과 협의) |
| **높음** | 전투 결과가 기록되지 않는다 | `HuntDeparture`는 출발까지만 처리하고, `RecordHunt`는 테스트 키에서만 불린다 | 반응 대사, 재도전 축약, 3패 힌트가 실제 흐름에서 동작하지 않는다 | `BattleManager.OnBattleFinished` 결과를 씬을 넘어 보관한다 (전투 담당과 협의) |

Canvas와 바깥 시스템 사이 참조(`DialogueManager.dialogueBox`, `DialogueBox.director`, `BubbleManager.template`, `NpcTalkCamera.menu` 등)는 바깥 프리팹의 오버라이드로 저장된다. 동작은 하지만, Canvas 프리팹만 따로 열면 비어 보이는 것이 정상이다.

### 9-5. 씬 교체 작업

씬마다 아래를 반복한다. 8-3의 5개 중 어떤 씬을 교체할지는 결정 4에 따른다.

1. 교체 전 값 기록: 카메라, 플레이어, 상점 창, NPC 위치
2. 기존 대화 오브젝트 삭제 (`RemovePrevious` 사용)
3. 프리팹과 NPC 프리팹 배치
4. `씬 연결` 실행 후 Binder 빈 칸 확인
5. 디자인 8 확인 표 실행

- 프리팹을 뽑기 전에 씬별 UI 값을 비교한다. 팀원이 자기 씬에서 손본 값이 있으면 DialogueTest 기준 프리팹에 반영할지 정한다
- 공용 씬이므로 담당 팀원과 시점을 맞추고 씬별로 따로 커밋한다
