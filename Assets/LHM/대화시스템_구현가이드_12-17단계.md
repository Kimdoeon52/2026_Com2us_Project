## 12. 스킵 + 오토 + 빨리감기

### 12-1. 목표

| 항목 | 내용 |
|---|---|
| 만드는 것 | 대화 중 **Esc 스킵 / Tab 오토 / Ctrl(홀드) 빨리감기**. 판단 기준인 **읽은 대사 줄 기록**과 세이브 |
| 근거 | 기획서 xiv 편의 기능, xv.1 입력 상태(대화), xv.4.1.b 읽은 대사 줄 저장 |
| 완료 조건 | Esc: 안 읽은 줄이 있으면 확인 창, 다 읽었으면 바로 스킵. Tab: 문장 길이에 비례해 자동 진행. Ctrl: **읽은 줄만** 빠르게 넘기고 안 읽은 줄에서 멈춤. 대화 시작 0.25초·줄마다 0.12초 확인 입력 무시 |
| 새 파일 | `DialogueInput.cs`, `Editor/Step12_SceneSetup.cs` |
| 바뀐 파일 | `DialogueBox`(전체 교체, 연결 칸 이름은 그대로), `DialogueHistory`(읽은 줄), `DialogueSaveData`(`readLines`), `DialogueLine`(`textKey`), `DialogueDatabase`(줄에 `textKey` 채움), `DialogueManager`(기록 연결, 닫힐 때 저장) |

### 12-2. 기획서 규칙과 구현

| 기획서 | 구현 |
|---|---|
| 스킵: 남은 대화 전체 건너뛰기, 안 읽은 대사가 있으면 확인 창 | 지금 줄부터 끝까지 중 안 읽은 줄이 1개라도 있으면 확인 창. Esc 한 번 더 = 스킵, 확인 키 = 계속 읽기 |
| 빨리감기: 누르고 있는 동안 읽은 대사만 빠르게 | Ctrl을 누르는 동안 **읽은 줄**이면 즉시 완성 + 0.06초마다 다음 줄. 연출 대기도 건너뜀. 안 읽은 줄에서 자동으로 보통 속도로 돌아온다 |
| 오토: 문장 길이에 비례 | 타자기가 끝난 뒤 `1초 + 글자 수 × 0.05초` 기다렸다가 다음 줄. Tab으로 켜고 끈다. 대화가 끝나도 켜진 상태 유지 |
| 스킵해도 스토리 진행은 정상 반영 | 대사 기록(본 횟수·사건 표시)은 대화를 **여는 순간** 남으므로 스킵해도 그대로 남는다. 연출은 `Close` → `director.EndDialogue()`로 원래대로 돌아간다 |
| 대화 시작 0.25초, 줄마다 0.12초 입력 무시 | 확인·스킵 입력에 적용. 기존의 "여는 프레임만 무시"를 시간 기준으로 바꿨다 |

### 12-3. 읽은 대사 줄 기록

| 항목 | 내용 |
|---|---|
| 무엇으로 기억하나 | 줄의 **문자열 키**(`textKey`, 예: `auction.greeting.1`). 대사 순서 번호가 아니므로 줄을 추가·삭제해도 기록이 어긋나지 않는다 (기획서 xv.4.2) |
| 언제 "읽음"이 되나 | 그 줄을 끝까지 보고 **다음 줄로 넘어갈 때** (확인 키·오토·빨리감기). 스킵으로 건너뛴 줄은 읽음이 아니다 |
| 저장 | 대화창이 닫힐 때 `DialogueManager`가 저장. 세이브 `dialogue.readLines`에 키 목록 |
| 확인 | F5 기록 출력 첫 줄 `[읽은 줄] N줄`, 대화창 로그의 `(읽음)` 표시 |

- 같은 문자열 키를 다른 대사에서 다시 쓰면 그 줄도 읽은 것으로 본다. 같은 문장이므로 의도한 동작이다

### 12-4. 스크립트 설명

#### `DialogueInput`

| 코드 | 설명 |
|---|---|
| `ConfirmPressed / SkipPressed / FastForwardHeld / AutoPressed` | `InputModeController`가 있으면 Dialogue 맵의 `Confirm / Skip / FastForward / Auto` 액션을 읽는다. 없으면(예전 테스트 씬) 키보드 Space·Enter·좌클릭 / Esc / Ctrl / Tab을 직접 읽는다 |
| 빨리감기만 `Held` | 누르고 있는 동안 동작하므로 "방금 눌림"이 아닌 "눌려 있음"을 본다 |

#### `DialogueBox` — `Update` 흐름

| 순서 | 처리 |
|---|---|
| 1 | Tab → 오토 켜기/끄기 |
| 2 | 스킵 확인 중이면 Esc(스킵) / 확인 키(취소)만 받고 끝. 확인 중에는 타자기도 멈춘다 |
| 3 | 입력 무시 시간이 지났고 Esc → 안 읽은 줄 수를 세어 확인 창 또는 바로 스킵 |
| 4 | 빨리감기 판단: Ctrl을 누르고 있고 **지금 줄이 읽은 줄** |
| 5 | 연출 대기 중: 빨리감기면 대기를 0으로, 아니면 시간 차감 |
| 6 | 빨리감기: 즉시 완성 → 0.06초마다 `Next` |
| 7 | 오토: 타자기가 끝난 뒤 문장 길이만큼 기다렸다가 `Next` |
| 8 | 확인 키: 타자 중이면 즉시 완성, 끝났으면 `Next` (6-7단계와 같음) |

| 새 인스펙터 칸 | 기본값 | 설명 |
|---|---|---|
| Skip Confirm | (12단계 배치가 생성) | 스킵 확인 창. 비어 있어도 확인 절차는 동작하고 콘솔에만 안내가 뜬다 |
| Status Text | (12단계 배치가 생성) | `AUTO` / `빨리감기 >>` 표시 |
| Open Input Delay | 0.25 | 대화 시작 직후 입력 무시 |
| Line Input Delay | 0.12 | 줄마다 입력 무시 |
| Fast Forward Interval | 0.06 | 빨리감기 줄 간격 |
| Auto Base Seconds / Auto Seconds Per Char | 1 / 0.05 | 오토 대기 시간 = 기본 + 글자 수 × 글자당 |

- Esc는 선택지의 `Cancel`(나가기)과 같은 키다. 대화 중에는 선택지가 `Talking` 상태라 Esc를 읽지 않으므로 겹치지 않는다
- 빨리감기는 글자 사운드가 나지 않는다 (`Complete`는 글자 이벤트를 보내지 않음)

#### `DialogueManager` 추가 부분

| 코드 | 설명 |
|---|---|
| `dialogueBox.SetReadLog(history)` | 대화창이 읽은 줄을 묻고 기록할 수 있게 기록 객체를 넘긴다 |
| `Closed += OnBoxClosed` → `Save()` | 대화 중에 늘어난 읽은 줄을 대화가 끝날 때 한 번 저장 |

### 12-5. 적용 방법

1. `Tools > Dialogue > 12단계 배치 (스킵 · 오토 · 빨리감기)` → 대화창 안에 `StatusText`(오른쪽 위)와 `SkipConfirm`(가운데, 꺼진 상태) 생성·연결
2. 위치·크기는 손으로 다듬는다
3. Ctrl+S → Play → **Shift+F12 필수**
   - 세이브에 `readLines` 칸이 새로 생겨, 예전 세이브는 다시 계산한 체크섬이 맞지 않는다 → 본 파일·백업 모두 거부되고 저장 금지 상태가 된다 (R-1 동작 표). 개발 중 세이브 호환은 대응하지 않는다 (기획서 8.j)

### 12-7. 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| Play 직후 `체크섬 불일치` / `저장하지 않습니다` | 12단계 이전 세이브 | Shift+F12 |
| Ctrl을 눌러도 아무 반응 없음 | 지금 줄이 안 읽은 줄 / 기록 미연결 | 로그에 `(읽음)` 표시가 있는 줄인지 확인. `DialogueManager`를 거치지 않고 연 대화(예전 Step05·06)는 기록이 없다 |
| Esc를 눌러도 반응 없음 | 대화 시작 0.25초 이내 / 입력 맵 꺼짐 | 잠시 후 다시. `[InputMode]` 로그로 Dialogue 상태인지 확인 |
| 확인 창이 안 보이는데 Esc 두 번에 스킵됨 | `Skip Confirm` 칸 비어 있음 | 12단계 배치 메뉴 다시 실행 |
| `StatusText`가 글자 없이 네모로 나옴 | 폰트에 글자 없음 | 9단계와 같은 한글 폰트 사용 (배치 메뉴는 `SpeakerName` 폰트를 복사) |

## 13. 백로그

### 13-1. 목표

| 항목 | 내용 |
|---|---|
| 만드는 것 | 대화 중 **L**로 지나간 대사를 다시 보는 창 (최근 200줄) |
| 근거 | 기획서 xiv 편의 기능(백로그), xv.1 입력 상태(대화: L 백로그), 로드맵 6장 (휠업 금지) |
| 완료 조건 | 대화 중 L → 백로그 열림(맨 아래 = 최신 줄). 방향키·휠·PgUp/PgDn으로 스크롤. L 또는 Esc로 닫힘. 열려 있는 동안 대화는 멈춤 |
| 새 파일 | `DialogueBacklog.cs`, `Editor/Step13_SceneSetup.cs` |
| 바뀐 파일 | `DialogueBox`(백로그 칸·열기/닫기·줄 추가), `DialogueInput`(`BacklogPressed`) |

### 13-2. 설계

| 항목 | 결정 | 이유 |
|---|---|---|
| 무엇이 쌓이나 | 대화창에 **표시된 줄** (화자 이름 + 본문). 지금 보고 있는 줄도 포함 | 스킵으로 건너뛴 줄은 표시되지 않았으므로 쌓이지 않는다 |
| 몇 줄까지 | 200줄. 넘으면 가장 오래된 줄부터 버림 (인스펙터 `Max Lines`) | 기획서 xiv |
| 저장 | **하지 않음.** 메모리에만 있고 게임을 끄면 비어 있다 | 기획서 xv.4.1 저장 항목에 없음. 세이브 형식도 바뀌지 않아 Shift+F12 불필요 |
| 여러 대화 | 대화가 끝나도 지우지 않고 이어서 쌓는다 (경매장 → 보스 진입 대사가 한 목록에) | 지난 대화를 다시 보는 것이 목적 |
| 여는 키 | L만. **휠업으로는 열리지 않는다** | 로드맵 6장. 휠은 열린 백로그 안의 스크롤 전용 |
| 열려 있는 동안 | 대화창 `Update`가 백로그만 처리하고 끝 → 타자기·오토·빨리감기·확인 키 모두 멈춤 | 백로그를 보는 중에 대사가 넘어가지 않게 |
| 시간 | 따로 UI 스택에 등록하지 않음 | 대화창이 이미 등록되어 있어 시계는 이미 멈춰 있다 |

### 13-3. 스크립트 설명

#### `DialogueBacklog`

| 코드 | 설명 |
|---|---|
| `Add(speaker, text)` | 줄 하나 추가. 200줄을 넘으면 앞에서 버림 |
| `Open()` | 목록을 한 글로 이어 붙여 `Content`에 넣고, 글 높이를 계산해 `Content` 높이로 정한 뒤 맨 아래로 스크롤 |
| `HandleScroll(deltaTime)` | ↑/↓ 누르는 동안 초당 900px, PgUp/PgDn 한 화면(90%), 휠 한 칸 80px. 0 ~ (글 높이 − 보이는 높이) 사이로 제한 |
| `Close()` / `Clear()` | 닫기 / 목록 비우기 (`Clear`는 지금 부르는 곳 없음) |

- 스크롤은 `ScrollRect` 대신 `Content`의 위치를 직접 옮긴다. EventSystem이 없는 씬에서도 휠이 동작하고, 입력을 한 곳(대화창 `Update`)에서만 받기 위해서다
- 화자 이름은 `Speaker Color`(기본 연한 주황), 내레이션 줄은 이름 없이 본문만
- 스크롤 키(방향키·PgUp/PgDn·휠)는 `.inputactions`를 거치지 않고 직접 읽는다. 백로그가 열려 있을 때(= 대화 입력 상태)만 읽으므로 필드·전투 입력과 겹치지 않는다

#### `DialogueBox` 추가 부분

| 순서 | 처리 |
|---|---|
| 맨 앞 | 백로그가 열려 있으면 L·Esc → 닫기 (닫은 뒤 0.12초 입력 무시), 아니면 스크롤만 하고 끝 |
| 스킵 확인 다음 | 입력 무시 시간이 지났고 L → 백로그 열기 |
| `ShowLine` | 줄을 띄울 때 `backlog.Add` |
| `Close` | 대화창이 닫히면 백로그도 닫음 |

- 스킵 확인 창이 떠 있는 동안에는 L이 동작하지 않는다 (Esc / 확인 키만)
- Esc로 백로그를 닫으면 그 Esc는 스킵으로 이어지지 않는다 (같은 프레임에 끝내고, 0.12초 입력 무시)

### 13-4. 적용 방법

1. `Tools > Dialogue > 13단계 배치 (백로그)` → 대화창이 들어 있는 Canvas의 맨 아래 자식(= 화면 맨 위)으로 `[Step13] Backlog` 생성, 대화창의 `Backlog` 칸 연결
   - `Panel`(꺼진 상태, 검정 90%) / `Title` / `Viewport`(RectMask2D) / `Content`(TMP)
   - 폰트는 대화창 본문 폰트를 복사
2. 크기·글자 크기는 손으로 다듬는다
3. Ctrl+S → Play (세이브 형식 변화 없음, Shift+F12 불필요)

### 13-5. Play로 확인 (확인 전)

| # | 할 일 | 기대 결과 |
|---|---|---|
| 1 | 대화 없이 L | 아무 일 없음 (필드 입력 상태) |
| 2 | 경매장 NPC 대화 → 3번째 줄쯤에서 L | 백로그 열림, `[Backlog] 열림 (3/200줄)`, 맨 아래에 지금 줄 |
| 3 | Space 연타, Tab, Ctrl | 대사가 넘어가지 않음 (백로그 중 멈춤) |
| 4 | L | 닫힘, 같은 줄에서 이어서 진행 |
| 5 | 다시 L → Esc | 백로그만 닫히고 **대화는 스킵되지 않음** |
| 6 | 대화를 끝내고 다른 NPC·보스 진입(B) 대화 → L | 이전 대화 줄이 위에 이어져 있음 |
| 7 | 줄이 화면을 넘을 만큼 쌓은 뒤 ↑ / 휠 위 / PgUp | 위로 스크롤, 맨 위에서 멈춤. ↓ / 휠 아래 / PgDn → 맨 아래에서 멈춤 |
| 8 | 백로그를 연 채 오토가 켜져 있던 경우 | 닫은 뒤 오토 이어서 동작 |
| 9 | 대화 중 휠 위 | 백로그가 **열리지 않음** |
| 10 | 대화창이 닫힐 때까지 진행 | 백로그가 열려 있었다면 함께 닫힘 (스킵 확인 → Esc 스킵 포함) |

### 13-6. 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| L을 눌러도 반응 없음 | 대화창 `Backlog` 칸 비어 있음 / 대화 시작 0.25초 이내 / 스킵 확인 창이 떠 있음 | 13단계 배치 메뉴 실행. `[InputMode]` 로그로 Dialogue 상태인지 확인 |
| `[Backlog] ... 연결되지 않은 칸` 경고 | `Panel`·`Viewport`·`Content Text` 중 빈 칸 | `[Step13] Backlog`를 지우고 메뉴 다시 실행 |
| 글자가 네모 | 폰트에 한글 없음 | `Content`·`Title` 폰트를 대화창 본문과 같은 한글 폰트로 |
| 백로그가 대화창 뒤에 가려짐 | `[Step13] Backlog`가 Canvas 자식 중 맨 아래가 아님 | Hierarchy에서 맨 아래로 이동 |
| 스크롤이 안 됨 | 줄이 화면보다 적음 (정상) | 줄을 더 쌓고 확인 |

## 14. 전투 바크

### 14-1. 목표

| 항목 | 내용 |
|---|---|
| 만드는 것 | 전투 중 **파츠 파괴 · 보스 부위 파괴 · 보스 그로기** 때 화면 하단에 한 줄 자막 (2초 표시 후 페이드) |
| 근거 | 기획서 iv(파츠 파괴·보스 전투 중 = 전투 바크, 자막만), xii.1 하단 자막, viii 쿨다운, ix 기본 대사 의무, x 전투 순간 변수, xv.2.3 UI 스택 미등록 |
| 완료 조건 | 파괴 시 자막, 보스 그로기·부위 파괴 시 자막. 시간·입력은 멈추지 않음 |
| 새 파일 | `BattleBarkPlayer.cs`, `BattleBarkSubtitle.cs`, `Step14_BarkTest.cs`, `Editor/Step14_SceneSetup.cs`, `03.Data/Dialogue/battle_bark.json` |
| 바뀐 파일 | `DialogueManager`(`TryBark`), `variables.json`(전투 순간 변수 5개), `strings_ko.json`(`bark.*`) |
| LHM 밖 | **수정 없음.** KKH `CombatDataHub`·`BossControllerBase`의 공개 이벤트를 구독만 한다 |

### 14-2. 설계

| 항목 | 결정 | 이유 |
|---|---|---|
| 대사 고르기 | 대사 풀 `battle_bark` 하나에서 4·5단계 선택 규칙 그대로 | 기획서 v. "왼팔 파괴"(조건 2개)가 "파츠 파괴"(조건 1개)보다 먼저 (vi.2) |
| 전투 순간 값 | 바크 직전에 `battle.*` 변수를 채우고, 고른 직후 기본값으로 되돌림 | 기획서 x "바크 발생 시점에만 존재" |
| 기록 | 본 횟수·쿨다운은 남기지만 **바크 때 세이브 파일을 쓰지 않음** | 전투 중 파일 쓰기 방지. 다음 저장(대화 종료 등) 때 함께 저장 |
| 줄 수 | 대사의 **첫 줄만** 사용 (여러 줄이면 로그에 표시) | 기획서 xii.1 "한 줄" |
| 겹침 | 새 바크가 나오면 이전 자막을 바로 교체. 단, 직전 바크 후 0.8초 이내는 무시 (`Min Interval`) | 연속 파괴로 자막이 깜빡이지 않게 |
| 대화창 | 대화창이 열려 있으면 바크 무시 | 보스 진입 대사 중 끼어들지 않게 |
| UI 스택 | 등록하지 않음 → 시계·입력 그대로 | 기획서 xv.2.3 |
| 기본 대사 | `bark_fallback`(조건·쿨다운 없음). 전용 대사가 모두 쿨다운이면 이것이 나옴 | 기획서 ix |

### 14-3. 전투 연결

| 사건 | 받는 곳 (KKH 코드) | 바크 |
|---|---|---|
| 내 파츠 파괴 | `CombatDataHub.OnPlayerPartBroken(BodyPart)` | `playerPartBroken` + 부위. 전투 중 파괴 수 +1 |
| 보스 부위 파괴 | `BossSnapshot.gimmickStates`에서 `isPhysicalBossPart`가 부서진 순간 (매 프레임 확인) + `OnBossGimmickBroken` | `bossPartBroken` + 기믹 ID (예: `TIRE_PART`) |
| 보스 그로기 | `BossControllerBase.OnGroggyChanged(true, …)` | `bossGroggy` + 보스 체력 % |

- 허브·보스는 1초마다 씬에서 찾아 연결한다. 전투 씬이 아니면 연결 없이 테스트 키로만 동작
- 보스 부위 파괴는 KKH 쪽에 이벤트가 없어 **상태를 매 프레임 비교**한다(`OnBossGimmickBroken`은 선언만 있고 호출하는 곳이 없음). KKH가 이벤트를 호출하게 되어도 같은 부위는 한 번만 바크한다
- 부위가 복구되었다가 다시 부서지면 다시 바크한다. 연결한 순간 이미 부서져 있던 부위는 바크하지 않는다
- 다른 파트에서 직접 부를 수도 있다: `NotifyPlayerPartBroken(part)`, `NotifyEnemyPartBroken(part)`, `NotifyBossPartBroken(id)`, `NotifyBossGroggy()`, 전투 시작 시 `ResetBattle()`

## 15. 비강제 말풍선

### 15-1. 목표

| 항목 | 내용 |
|---|---|
| 만드는 것 | 머리 위에 잠깐 떴다 사라지는 한 줄 — **관중 · NPC 반응 · 근접 혼잣말** |
| 근거 | 기획서 iii(비강제 말풍선, 같은 선택 규칙), iv(노출 지점), viii(사건당 1회·쿨다운·반응 묶음), xii.1(관중 동시 최대 3개), xv.2.3(UI 스택 미등록), xv.3(이벤트 큐 반응 말풍선) |
| 완료 조건 | 관중 랜덤 말풍선, 이벤트 큐의 반응 말풍선이 NPC 근처에서 1회, NPC 근처 혼잣말 |
| 새 파일 | `BubbleView.cs`, `BubbleManager.cs`, `CrowdBubbles.cs`, `NpcBubbles.cs`, `Step15_BubbleTest.cs`, `Editor/Step15_SceneSetup.cs`, 데이터 `crowd.json`, `mono_receptionist.json`, `mono_junkdealer.json`, `mono_auctioneer.json` |
| 바뀐 파일 | `DialogueManager`(`TryPickLine`·`TryPlayBest`·`TryGetFirstLine`, `TryBark`는 `TryPickLine`으로), `DialogueEventQueue`(`Evaluate(label)`, `IsFieldIdle(manager)` 공개), `event_dialogues.json`·`dialogue_triggers.json`(길드 패배 반응 말풍선 2개), `strings_ko.json` |

### 15-2. 세 가지 말풍선

| 종류 | 언제 | 대사 풀 | 기록·저장 |
|---|---|---|---|
| 관중 | 2.5~5초마다 무작위 관중 1명. 관중 말풍선은 **동시 최대 3개** | `crowd` | 본 횟수·쿨다운만 (저장 안 함) |
| NPC 반응 | 이벤트 큐에서 넘어온 반응 말풍선을, 플레이어가 그 NPC **4m 안에 들어오면 1회** | 대사 ID (`event_dialogues.json`의 `bubble_*`) | 기록 + **즉시 저장** (사건당 1회가 껐다 켜도 유지되도록) |
| 근접 혼잣말 | 플레이어가 NPC **3m 안에 들어서는 순간**. NPC별 10초 간격 | `mono_` + NPC의 Speaker Id | 본 횟수·쿨다운만 (저장 안 함) |

- 세 종류 모두 4·5단계 선택 규칙을 그대로 쓴다 (기획서 iii.1). 대사가 여러 줄이면 첫 줄만
- UI 스택에 등록하지 않는다 → 시계·이동이 멈추지 않는다 (기획서 xv.2.3)
- 대화창이 열려 있는 동안은 말풍선을 숨기고(시간은 계속 흐름), 새 말풍선도 만들지 않는다
- 반응 말풍선이 뜬 NPC는 그 자리에서 혼잣말을 하지 않는다 (같은 10초 간격에 묶임)

### 15-3. 반응 말풍선 흐름

```
00시 / 귀가 → DialogueEventQueue.Evaluate → bubble 항목 적재
  → 필드 복귀 + 0.5초 → BubbleRequested(대사 ID)
  → NpcBubbles: 대사 첫 줄의 화자(speakerId)로 NPC 지정, 대기 목록에 추가
  → 플레이어가 그 NPC 4m 안 → TryPlayBest(대기 중인 그 NPC의 반응 전부) → 1개 출력·기록·저장
  → 나머지 중 이제 나올 수 없는 것(같은 묶음 등)은 제거
```

| 항목 | 내용 |
|---|---|
| NPC 찾기 | 대사 첫 줄의 `speaker` = `NpcInteractable`의 `Speaker Id` (예: `receptionist`, `auctioneer`) |
| 여럿 대기 | 같은 NPC에 반응이 2개 이상이면 선택 규칙으로 하나 (예: `bubble_guild_after_defeat_wheel`(조건 2개)이 일반 패배(조건 1개)보다 먼저). 같은 묶음 `guild_hunt_reaction`이라 나머지는 제거 |
| 대화창 반응과 관계 | `guild_after_defeat`(대화창)과 같은 묶음. 말풍선을 먼저 보면 E → 대화에서 패배 반응이 안 나오고, 대화를 먼저 하면 말풍선이 제거된다 (기획서 viii.1) |
| 저장 | 대기 목록은 저장하지 않는다 (이벤트 큐와 같음, 11-2 참고) |

- 귀가(필드 복귀) 시 평가: 전투 담당이 필드 복귀 시점에 `queue.Evaluate("귀가")`를 부르면 된다. 지금은 테스트 키 H

### 15-4. 스크립트 설명

### 16-2. 검사 항목

| 구분 | 항목 | 어디서 |
|---|---|---|
| 오류 (기존) | JSON 문법, 빈 칸, 중복 ID·키·변수, 없는 변수·문자열·화자, 잘못된 값·연산자·band·display, 소비 규칙 값, 기본 대사 누락, 이전 ID 충돌 | 실행·검사 메뉴 공통 (`DialogueDatabase`) |
| 오류 (신규) | **조건 모순 — 절대 나올 수 없는 대사**. 같은 변수의 조건끼리 비교: `>= 5`와 `< 3`, `== a`와 `== b`, `== a`와 `!= a`, enum의 허용값을 `!=`로 전부 제외 등 | 공통 |
| 오류 (신규) | **순환 참조** — 이전 ID(`formerIds`)에 자기 자신, 두 대화가 서로를 이전 ID로 적음 | 공통 |
| 오류 (신규) | 트리거: queue 값, 없는 대화, 중복, **말풍선 첫 줄에 화자 없음**(NPC를 못 찾음) | 공통 (`DialogueTriggerTable.Validate`) |
| 경고 | 어떤 대사도 쓰지 않는 문자열 키 (`speaker.`·`menu.` 제외) | 공통 (검사 메뉴에서만 표시) |
| 경고 | 바크·관중·혼잣말·말풍선 대사가 2줄 이상 (첫 줄만 나옴), 혼잣말 화자가 풀 이름(`mono_` 뒤)과 다름 | 검사 메뉴 |

- **순환 참조에 대해**: 지금 데이터 형식에서 서로를 가리킬 수 있는 것은 이전 ID뿐이다. 조건은 변수만, 연출은 종류·값만 가지므로 다른 조건·연출을 부를 수 없어 순환이 생기지 않는다. 나중에 "조건 묶음 재사용"이나 "연출 프리셋"처럼 서로를 부르는 구조를 추가하면 이 검사를 함께 늘린다
- 경고는 빌드를 막지 않는다

### 16-3. 언제 검사하나

| 시점 | 동작 |
|---|---|
| `Tools > Dialogue > 데이터 검사` | `03.Data/Dialogue`의 JSON 전부(하위 폴더 제외)를 검사 → 결과 창 + 콘솔 |
| JSON 저장 (Unity가 다시 불러올 때) | 자동 검사 → 콘솔에만 `[DialogueData] 저장 시 자동 검사: 통과 / 오류 n건` |
| 빌드 시작 | 검사 → 오류가 있으면 **`BuildFailedException`으로 빌드 중단**. 통과하면 패킹 파일을 새로 만든 뒤 빌드 진행 |
| Play (`DialogueManager.Awake`) | 기존과 같은 검사. 실패하면 폴백 (16-5) |

- 파일 분류: `strings_ko.json` = 문자열, `variables.json` = 변수, `dialogue_triggers.json` = 트리거, 나머지 = 대사 풀
- **빌드 검사는 이 프로젝트의 모든 빌드에서 돈다** (다른 팀원의 빌드 포함). 대사 데이터 오류가 있으면 팀 빌드도 멈추므로, JSON을 고친 뒤 자동 검사 로그를 꼭 확인할 것

### 16-4. 빌드 패킹

| 항목 | 내용 |
|---|---|
| 파일 | `03.Data/Dialogue/Packed/dialogue_pack.bytes` (TextAsset) |
| 내용 | 대사 풀 전부 + 문자열 + 변수 JSON을 한 묶음으로 → SHA-256 체크섬 → GZip 압축 |
| 만드는 때 | 빌드 직전 자동 / `Tools > Dialogue > 데이터 패킹` / 16단계 배치 메뉴 |
| 읽는 때 | **빌드**: `Packed Data`가 연결되어 있으면 항상 패킹 파일부터. **에디터**: `Use Pack In Editor`를 켰을 때만 (평소에는 JSON을 바로 읽어 수정이 즉시 반영) |
| 트리거 | 패킹하지 않는다. 이벤트 큐가 자기 `Triggers Json`을 읽는다 (빌드 전 검사는 함께 함) |

- 원본 JSON 연결(`Pool Jsons` 등)도 그대로 둔다. 씬이 참조하므로 빌드에도 들어가고, 패킹 파일이 손상되었을 때 대신 읽는다
- 패킹 파일은 빌드할 때마다 새로 만들어진다. git에는 올려도 되고 안 올려도 된다 (빌드가 다시 만듦)

### 16-5. 로드 순서와 폴백

```
패킹 파일 (빌드, 또는 Use Pack In Editor)
  └ 손상·체크섬 불일치·내용 오류 → 원본 JSON
        └ 실패 → 기본 대사 폴백 모드
```

| 폴백 모드 | 동작 |
|---|---|
| 말 걸기 (`Talk`) | 화자 없이 `...` 한 줄 → 닫히면 평소처럼 진행 (선택지 종료, **보스 진입 대사 뒤 전투 시작**) |
| NPC 선택지 | 그대로 열림. 선택지 이름은 내장 문구(토벌 신청 / 랭킹 보드 / 포상 수령 / 대화 / 상점 열기 / 나가기) |
| 이벤트 대사·바크·말풍선 | 나오지 않음 (트리거도 읽지 않음) |
| 세이브 | **읽지도 쓰지도 않음** — 폴백 중 저장해서 진짜 기록을 지우는 일을 막음 |
| 콘솔 | `[DialogueManager] 대사 데이터를 불러오지 못해 기본 대사 폴백으로 동작합니다…` (에러) |

- 예전에는 로드 실패 시 `IsReady`가 꺼져 **NPC 선택지 자체가 열리지 않았다** (상점·토벌 신청까지 막힘). 폴백 모드에서는 대사만 `...`이 되고 나머지 진행은 막히지 않는다 (기획서 xvi.3.b)
- `Debug Force Fallback`(인스펙터)을 켜면 데이터를 읽지 않고 바로 폴백 모드로 시작한다. 에디터·개발 빌드에서만 동작

### 16-6. 적용 방법

1. `Tools > Dialogue > 데이터 검사` → `통과` 확인
2. `Tools > Dialogue > 16단계 배치 (패킹 데이터 연결)` → 검사 + 패킹 + 씬의 `DialogueManager`에 `Packed Data` 연결
3. Ctrl+S

| 7 | 폴백 상태에서 F5 / 세이브 폴더 | 기록 비어 있음, 세이브 파일 수정 시각 그대로 (쓰지 않음) |
| 8 | `Debug Force Fallback` 끄고 Play | 예전 기록 그대로 불러옴 |
| 9 | 아무 대사 JSON에 `{ "variable": "hunt.count", "op": ">=", "value": "5" }`, `{ "variable": "hunt.count", "op": "<", "value": "3" }` 두 조건 추가 → 저장 | 콘솔 `저장 시 자동 검사: 오류 1건 … 조건끼리 모순이라 절대 나올 수 없습니다` |

| 11 | `strings_ko.json`에 쓰지 않는 키 추가 → 데이터 검사 | 경고 1건 (빌드는 통과) |

### 16-8. 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 빌드가 `[DialogueData] … 빌드를 중단합니다`로 실패 | 대사 데이터 오류 | 데이터 검사 메뉴에서 오류 목록 확인 |

## 17. 대사 작성 환경 — CSV 변환

### 17-1. 목표

| 항목 | 내용 |
|---|---|
| 결정 | 기획서 xviii.1 "대사 작성 방식" → **엑셀·구글 시트로 작성 → CSV 저장 → Unity가 JSON으로 변환** (2026-11-01) |
| 만드는 것 | JSON → CSV 내보내기, CSV → JSON 가져오기, CSV 저장 시 자동 변환. 문자열 테이블 자동 관리 |
| 새 파일 | `Editor/DialogueSheetTools.cs`, (생성물) `03.Data/Dialogue/Sheets/*.csv` |
| 바뀐 파일 | `Editor/DialogueDataTools.cs` (`Check`가 저장 전 내용으로도 검사) |
| 런타임 | **변화 없음.** 게임은 지금처럼 JSON(빌드는 패킹 파일)을 읽는다 |

### 17-2. 작업 흐름

```
(처음 1번) Tools > Dialogue > CSV 내보내기  →  Sheets/풀이름.csv
엑셀·구글 시트에서 CSV 편집 → CSV UTF-8로 저장 (Sheets 폴더에 덮어쓰기)
  → Unity로 돌아오면 자동 변환
       ① CSV 읽기 ② 키 자동 생성 ③ 변환 결과를 16단계 검사
       ④ 통과하면 풀 JSON + strings_ko.json 저장 / 실패하면 아무것도 저장하지 않고 콘솔에 오류
  → JSON 저장 → 16단계 자동 검사 로그
```

- **CSV가 있는 풀은 CSV가 원본이다.** JSON을 직접 고치면 다음 CSV 변환 때 덮어써진다. JSON을 고쳤다면 CSV 내보내기를 다시 해서 맞춘다
- CSV가 없는 풀(내보내지 않은 풀)은 지금처럼 JSON이 원본
- 변수(`variables.json`)와 트리거(`dialogue_triggers.json`)는 CSV 대상이 아니다 (지금처럼 JSON)
- 여러 CSV를 한 번에 다시 변환: `Tools > Dialogue > CSV 가져오기 (CSV → JSON, 전체)` (결과 창 표시)

### 17-3. CSV 형식

| 행 | 내용 |
|---|---|
| 1행 (선택) | `#eventOnly`, `true` — 이벤트 전용 풀일 때만. **풀 ID = 파일 이름** (v6, 다르면 검사 오류) |
| 머리글 | `id, band, sub, conditions, consume, display, background, formerIds, speaker, expression, text, effects, key` (첫 칸이 `id`인 행). 칸 순서는 바꿔도 된다 |
| 데이터 | **한 행 = 대사 한 줄.** 대화의 첫 줄에만 `id`와 대화 칸(band~formerIds)을 적고, 이어지는 줄은 `id`를 비운다 |
| 빈 행 | 무시 (대화 사이에 넣어도 됨) |
| `#`로 시작하는 행 | 메모 (무시, `#eventOnly` 제외) |

| 칸 | 적는 법 | 예 |
|---|---|---|
| `band` | Critical / Story / Reactive / Progress / Ambient / Fallback | `Reactive` |
| `sub` | 세부 순위 0~99 (비우면 0) | `10` |
| `conditions` | `변수 연산자 값`을 `;`로 나열. 빈 문자열은 `""` | `hunt.lastResult == lose; hunt.lastBoss == boss.wheel` |
| `consume` | `maxPlays=N` / `perEvent=변수` / `group=묶음` / `cooldown=초` 를 `;`로 | `perEvent=hunt.count; group=guild_hunt_reaction` |
| `display` / `background` | bottom(비우면) / fullscreen / intermission, 배경 ID | `fullscreen`, `bg.prologue` |
| `formerIds` | 이전 ID를 `;`로 | `old_id_1; old_id_2` |
| `speaker` | 화자 ID (비우면 내레이션) | `receptionist` |
| `expression` | 표정 | `smile` |
| `text` | **실제 문장** | `토벌, 잘 안 풀렸다면서요?` |
| `effects` | `종류(값)`을 `;`로. 소리·BGM은 ID, `wait`는 끝날 때까지 대기 | `zoom(1.2); shake(0.3); sound(sfx.stamp); fadeOut(1, wait)` |
| `key` | 문자열 키. **새 줄은 비워 두면 자동 생성** (`대화ID.줄번호`) | `guild.greeting.1` |

- 조건 값에는 `;`를 쓸 수 없다 (구분자)
- 문장에 쉼표·줄바꿈이 있어도 된다 (엑셀이 따옴표로 감싸서 저장)

### 17-4. 문자열 키 처리

| 경우 | 처리 |
|---|---|
| `key` 있음 + `text` 있음 | 그 키의 문장을 `text`로 (바뀌었으면 변경) |
| `key` 비움 + `text` 있음 | 새 키 `대화ID.줄번호` 생성 (겹치면 `_2`, `_3`…) → 추가 |
| `key` 있음 + `text` 비움 | 기존 문장을 그대로 씀 (다른 풀의 문장을 같이 쓸 때). 없는 키면 오류 |
| 같은 키를 여러 행에서 다른 문장으로 | 오류 |
| 이전에 이 풀이 쓰던 키가 CSV에서 사라짐 | 다른 풀도 안 쓰면 `strings_ko.json`에서 삭제 (`speaker.`·`menu.` 제외) |
| 다른 풀도 쓰는 키의 문장을 바꿈 | 변환은 되지만 경고 (그쪽 대사도 바뀜) |

- 새 키는 같은 풀의 기존 키 바로 아래에 들어간다. 파일의 빈 줄 구분은 유지된다
- **읽은 대사 기록은 키 기준**(12단계)이므로, 문장만 고치면 "읽음"이 유지되고 키를 바꾸면 새 줄로 취급된다

### 17-5. 엑셀·구글 시트 주의

| 도구 | 저장 방법 |
|---|---|
| 엑셀 | **다른 이름으로 저장 → "CSV UTF-8(쉼표로 분리)"**. 그냥 "CSV"는 한글이 깨진 형식(CP949)이라 변환이 거부된다 (`UTF-8이 아닌 파일입니다`) |
| 구글 시트 | 파일 → 다운로드 → 쉼표로 구분된 값(.csv) → `Sheets` 폴더의 같은 이름 파일에 덮어쓰기 |
| 공통 | 엑셀이 `1.0`을 `1`로, `0.05`를 `.05`로 바꿔도 같은 값으로 읽는다. `key` 칸이 날짜·숫자로 바뀌지 않게 텍스트 서식 권장 |

- 내보낸 CSV는 BOM 포함 UTF-8이라 엑셀에서 더블클릭으로 열어도 한글이 정상

### 18-2. 보스별 진입 (xx)

```
게임(보스 기록) ── 진입 직전 ──▶ BossEntryDialogue.Play(bossId, 난이도, 그 보스 도전 수, 그 보스 패배 수, 끝나면)
                                   └ hunt.targetBoss / targetDifficulty / bossAttemptCount / bossLoseCount 설정 → boss_entry 풀에서 선택
```

| 대사 (`boss_entry.json`) | 조건 |
|---|---|
| `boss_entry_retry` | 없음 — 모든 보스 공통 안전장치 |
| `boss_entry_first` / `_first_hell` / `_retry_wheel` / `_retry_hell` / `_hint` | `hunt.targetBoss == boss.wheel` + 기존 조건 |

- **보스별 횟수는 게임이 보관한다** (기획서 xx.0.2.a). 대사 시스템은 진입 때 받은 값만 본다
- 테스트에서는 `Step09_DialogueDebug`가 보스별 도전·패배 횟수를 **메모리에** 보관한다 (Play를 끄면 0). **G**로 대상 보스 전환(호이루 ↔ 쿄다이), F1 패배 / F2 승리는 대상 보스 기준
- 바크·관중 대사도 `hunt.targetBoss`로 보스별 대사를 낼 수 있다 (`bark_boss_groggy_low`는 호이루, `bark_kyodai_groggy`는 쿄다이, 관중 응원도 보스별)
- 쿄다이 부위 ID는 아직 전투 코드에 없어 부위 파괴 바크는 만들지 않았다 (기획서 xx.2 — 정해지면 `battle.bossPartId` 조건으로 추가)

### 18-3. 튜토리얼 재생 방법 (xxi)

| 재생 방식 (xxi 표) | 부르는 방법 | 예시 대사 |
|---|---|---|
| **UI 직접** — UI 화면 위 안내 | 그 UI가 열릴 때 `manager.PlayDialogueIfAvailable("tutorial_…")`. 이미 봤으면 조용히 `false` | `tutorial_t3_map` (지도), `tutorial_t9_hunt_apply` (토벌 신청) |
| **이벤트 큐** — 필드에서 시작 | 게임 사건 때 `queue.Enqueue(id, DialogueEventKind.System)`, 또는 트리거 목록에 넣고 00시·귀가 평가 | `tutorial_t12_first_defeat` (트리거, 귀가 평가, `hunt.loseCount >= 1`) |
| **전투 직접** — 하단 자막 | `barks.PlaySubtitleDialogue("tutorial_…")`. 여러 줄을 2초씩 차례로, 재생 중에는 바크 보류. 시간 안 멈춤 | `tutorial_t10_battle` (첫 전투 시작 직후) |

- 모두 `maxPlays: 1` — 열리는 순간 "봤음"으로 기록되므로 **스킵해도 다시 나오지 않는다** (xxi.0.4)
- `tutorial` 풀은 이벤트 전용(`eventOnly`)이라 기본 대사가 없어도 된다 (ix.3)
- 이벤트 큐는 UI 스택이 비어 있을 때만 출력하므로, UI 위 안내를 이벤트 큐로 보내면 UI를 닫은 뒤에야 나온다 (xv.3.3.a) — 그래서 UI 안내는 직접 재생
- T1~T19 중 4개만 예시로 만들었다. 나머지는 각 시스템 UI가 생기면 같은 방법으로 추가

## 디자인 3. NPC 클로즈업 카메라

| 항목 | 내용 |
|---|---|
| 흐름 | NPC 앞에서 E → **페이드 아웃** → 메인 카메라 끄고 클로즈업 카메라 켬(플레이어 근처) → **페이드 인과 동시에 NPC 주위를 돌며 접근** → 정지 거리에서 멈춤 → 선택지 → "대화" 시 대화창. 상호작용이 끝나면 페이드 → 메인 카메라 복귀 |

| 바뀐 파일 | `PlayerInteractor`(`Talk Camera` 칸, 비어 있으면 예전처럼 바로 선택지), `NpcChoiceMenu`(`Ended` 이벤트), `NpcInteractable`(`Close Up Focus Offset`, `Close Up Point`), `DialogueDirector`(`UseCamera` — 대사 확대·흔들림을 클로즈업 카메라에 적용) |
| 시간·입력 | 연출 시작부터 복귀까지 UI 스택에 등록 → 시계 정지, 대화 입력 상태(이동 불가). 이벤트 큐·말풍선도 끼어들지 않음 |
| 대상 | NPC 상호작용(E)만. 보스 진입·이벤트 대사·튜토리얼은 카메라 연출 없음 |

### 카메라 경로

```
NPC 머리(Focus) 기준 원 궤도
  시작: 플레이어 뒤 startBehindPlayer m, 각도 startAngle, 높이 startHeight
  끝:   거리 stopDistance, 각도 closeUpAngle, 높이 closeUpHeight  (moveSeconds 동안, ease 곡선)
  항상 Focus + lookOffset을 바라봄, 시야각은 메인 카메라 → closeUpFieldOfView
```

| 인스펙터 칸 (`NpcTalkCamera`) | 기본값 | 설명 |
|---|---|---|
| Fade Out / Fade In Seconds | 0.25 / 0.35 | 검정으로 / 검정에서. 페이드 인은 접근과 동시에 진행 |
| Approach | PlayerSide | 궤도 기준 방향. PlayerSide = NPC→플레이어 쪽, MainCameraSide = NPC→메인 카메라 쪽 (XY 테스트 씬은 배치 메뉴가 이쪽으로 설정) |
| Start Behind Player / Start Height / Start Angle | 1.2 / 0.6 / -35 | 시작 위치 (플레이어 어깨 뒤) |
| Stop Distance / Close Up Height / Close Up Angle | 1.6 / 0.05 / 20 | 정지 위치. 각도 차이(-35 → 20)가 회전량 |
| Look Offset | (0, -0.15, 0) | 바라보는 점. 음수면 얼굴이 화면 위쪽으로 (하단 대화창에 가리지 않게) |
| Close Up Field Of View | 40 | 0이면 시야각 그대로 |
| Move Seconds / Ease / Hold Seconds | 1.2 / EaseInOut / 0.15 | 접근 시간, 속도 곡선, 정지 후 선택지까지 대기 |
| Disable Main Camera | 켬 | 클로즈업 동안 메인 카메라 끔. 메인 카메라를 쓰는 Screen Space - Camera Canvas는 그동안 클로즈업 카메라로 옮겼다가 되돌림 |

- NPC별로 구도를 직접 정하고 싶으면 NPC 자식으로 빈 오브젝트를 만들어 `Close Up Point`에 넣는다 → 그 위치·회전으로 접근 (궤도 계산 대신)
- `Close Up Focus Offset`(기본 0, 1.5, 0): NPC 머리 위치. Scene 뷰에서 NPC를 선택하면 분홍 구로 보인다

1. `Tools > Dialogue > NPC 클로즈업 카메라 배치` → `[TalkCam] NpcTalkCamera`(+ 꺼진 `CloseUpCamera`, 메인 카메라 설정·URP 설정 복사), Canvas 맨 위 `[TalkCam] Fade` 생성, PlayerInteractor 연결
2. Ctrl+S → Play (세이브 형식 변화 없음)

### 카드 상태

| 상태 | 조건 | 표시 | 선택 |
|---|---|---|---|
| 진행 중 | 이전 지역 클리어(첫 지역은 항상), 이 지역 미클리어 | 금색 지역 태그, `진행 중` | 가능 |

### 기획서와 다른 점

- 기획서 xi.2 "대사 중간에 고르는 분기 선택지는 두지 않는다" — 이번 예/아니요는 **대사 데이터의 분기가 아니라 이 흐름 전용 확인 창**이다. 대사 데이터 형식에는 선택지가 없고, `SeasonRaceCall`이 마지막 줄을 띄워 둔 채 `DialogueChoice`를 연다. 기획서에 예외로 적어 둘 것
- 기획서 xxi T19 "시즌 정산·레이스 선택 — 첫 시즌 종료 길드 연락"과 같은 지점. 이벤트 큐(system) 대신 전화 연출로 구현

### 대화창 추가 기능

| 기능 | 사용 |
|---|---|
| `SetTextArgument("boss", "호이루")` | 문장의 `{boss}`를 바꿔 표시 (백로그·로그도 바뀐 문장). `ClearTextArguments()`로 지움 |
| `HoldOnLastLine(콜백)` | 다음에 여는 대화의 마지막 줄이 다 나오면 닫지 않고 멈춘 뒤 콜백. 멈춘 동안 확인·스킵·오토 입력 무시. 스킵(Esc)은 마지막 줄로 이동해 멈춤. 선택 후 `Close()` |

### 선택지 (`DialogueChoice`)

- ←↑ / →↓ / W·S 이동, **Enter·Z·E 결정**, 마우스 클릭, **Esc = 아니요**. **Space는 결정하지 않는다** (대사 넘기던 Space로 "예"가 바로 골라지는 문제, 2026-11-02 수정)
