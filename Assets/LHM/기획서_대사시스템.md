## i. 레퍼런스: Hades (반응형 대사)

1. 플레이어가 겪은 일(패배, 승리, 경매 결과, 순위 변동 등)을 NPC가 알고 반응한다
2. 같은 장소에 다시 와도 상황에 따라 다른 대사가 나온다

## ii. 대사는 코드가 아닌 데이터(JSON)로 관리한다

1. 대사 추가·수정 시 프로그래머 작업 없이 데이터만 수정

---

## iii. 대사 방식

| 방식 | 설명 | 플레이 정지 | 적용 |
|---|---|---|---|
| 반응형 대사 | 상황에 맞는 대사를 데이터에서 골라 출력 | 정지 (바크 제외) | 메인 스토리, 허브 NPC 대화, 보스 진입, 전투 바크 |
| 비강제 말풍선 | 머리 위에 잠깐 떴다 사라지는 한 줄 | 없음 | 관중, NPC 반응(패배·유찰 등), 근접 혼잣말 |

1. 비강제 말풍선도 반응형 대사와 같은 선택 규칙(v)으로 대사를 고른다
2. 플레이어가 무시해도 진행에 영향이 없다

## v. 대사 선택 규칙 [변경: 예시 표기]

| 단계 | 의미 | 예시 |
|---|---|---|
| 최우선 (Critical) | 반드시 먼저 나와야 하는 대사 | 프롤로그, 보스 첫 등장, 3패 후 기믹 힌트 |
| 스토리 (Story) | 스토리 진행 | 레이스 첫 참가, NPC 첫 만남 |
| 반응 (Reactive) | 방금 일어난 일 | 직전 **토벌** 패배/승리, 경매 정산 결과, 순위 급등락 |
| 진행 (Progress) | 누적 진행 | **토벌 5승 달성**, 시즌 종료 D-7 |
| 잡담 (Ambient) | 상황 무관 | 관중 반응 |
| 기본 (Fallback) | 조건 없는 기본 대사 | NPC 평상시 한마디 |

- 기획자는 숫자가 아닌 의미로 단계를 고른다
- 같은 단계 안에서 순서 조정이 필요하면 세부 순위(0~99)를 쓴다

## vi. 같은 단계일 때

1. 세부 순위가 높은 대사
2. 조건이 더 구체적인 대사 (예: "바퀴 보스에게 패배"가 "그냥 패배"보다 먼저)
3. 덜 본 대사
4. 더 오래전에 본 대사
5. 위가 모두 같으면 무작위

## vii. 스토리 대사 간격 [변경]

1. 연속된 이야기는 시간이 아니라 진행 상황으로 나눈다
   a. **레이스 진행**: 레이스 첫 참가, 순위 구간 진입, 시즌 1위, 다음 레이스 해금
   b. **캐릭터별 진행**: 해당 캐릭터와 관련된 사건 (그 캐릭터의 이전 대사 시청 등)
2. 방문당 대화 횟수 제한은 없다
   a. 간격은 위 진행 조건으로만 조절한다
3. 경매장 NPC의 서사 대사도 같은 방식으로 개방한다
   a. **관계도 수치는 개방 조건으로 쓰지 않는다** (x.1)

## viii. 소비 규칙

| 규칙 | 의미 | 예시 |
|---|---|---|
| 1회 | 게임 전체에서 1번 | 첫 만남, 챕터 대사 |
| N회 | 게임 전체에서 N번까지 | 특정 보스 패배 반응 2회 |
| 사건당 1회 | 같은 사건(패배 1회, 유찰 1회)에 대해 1번. 다음 사건이 생기면 다시 반응 | NPC 반응 말풍선 |
| 쿨다운 | 출력 후 N초 동안 다시 안 나옴 | 전투 바크, 관중 말풍선, 근접 혼잣말 |

1. 같은 사건에 대한 여러 버전의 반응(대화창·말풍선, 일반·특정 보스)은 **반응 묶음**으로 묶어 한 번만 반응한다

## ix. 기본 대사 의무

1. 허브 NPC, 관중, 전투 바크는 조건 없는 기본 대사를 최소 1개 가진다
2. 조건이 모두 빗나가도 NPC가 침묵하지 않게 하기 위함

## x. 대사 조건 변수 [변경]

| 분류 | 변수 | 내용 |
|---|---|---|
| 시간 | 요일, 월, 시즌 일차, 시즌 종료 D-7 여부 | |
| 토벌 | 직전 토벌 결과 | 없음 / 승리 / 패배 |
| 토벌 | 직전 토벌 보스 ID, 직전 토벌 난이도 | 난이도: 아주 쉬움 / 쉬움 / 보통 / 어려움 / 헬 |
| 토벌 | 현재 보스 패배 횟수 | 기믹 힌트 개방 조건. **보스 기준**으로 센다 (난이도 무관) |
| 토벌 | 누적 승리 / 패배 수, 토벌 횟수 | 토벌 횟수는 사건당 1회 판정용 |
| 랭킹 | 현재 순위 구간 | 1 / 2~10 / 11~30 / 31~100 / 101+ |
| 랭킹 | 전일 대비 등락, **10위권 첫 진입 여부** | 서사 이벤트 "첫 10위권 진입" |
| 플레이어 | 기본 파츠 사용 중 여부 | 회생 루트 반응 |
| 플레이어 | 전투 중 파괴된 파츠 수, 코어 레벨 | 바크, 서사 이벤트 |
| 경매 | 최근 정산 결과, 정산 횟수 | 없음 / 판매 / 유찰. 정산 횟수는 사건당 1회 판정용 |
| 진행 | 현재 레이스 ID, 레이스 진행 단계, 시즌 1위 달성 여부 | 스토리 대사 간격 판정용 |
| 진행 | 스토리 챕터 | 대사 시스템이 직접 관리 |
| 전투 순간 | 파괴된 부위, 관중 반응 순간, 보스 체력 비율 | 바크·말풍선 발생 시점에만 존재 |

1. NPC 관계도는 대사 조건으로 사용하지 않는다
2. 대사는 조건을 읽기만 한다
   a. 골드, 파츠, 관계도 등 게임 수치는 대사로 바꿀 수 없다
   b. 대사가 바꿀 수 있는 값은 스토리 챕터 등 대사 전용 값뿐

## xi. NPC 상호작용 선택지 [변경]

1. 필드에서 NPC에게 E → 선택지 표시

| NPC | 선택지 |
|---|---|
| 길드 접수원 | 토벌 신청 / 랭킹 보드 / 포상 수령 / 대화 / 나가기 |
| 고물상 아저씨 | 상점 열기 / 대화하기 / 나가기 |
| 그 외 허브 NPC | 대화 / 나가기 |

2. 선택지는 대화 흐름을 나누는 분기 대사가 아닌 **행동 메뉴**다
   a. 대사 내용 중간에 고르는 분기 선택지는 두지 않는다
3. "대화"가 아닌 선택지는 해당 시스템 UI로 넘긴다 (토벌 신청, 랭킹 보드, 포상 수령, 상점)
   a. 상점을 닫으면 대화도 즉시 종료되고 처음 상태로 돌아간다 (o. 물품 판매 시스템)
4. 판돈 선택지는 없다

## xii. 연출 형식 [변경: 말풍선 사용처]

### 1. 표시 방식별 구성

| 방식 | 구성 | 사용처 |
|---|---|---|
| 풀스크린 + 대사창 | 배경 연출 + 하단 대사창 | 프롤로그, 레이스 서사 이벤트 |
| 인터미션 | 전용 사운드 + 차별화된 카메라 워크 + 대사창 | A 총수 인터미션 |
| 하단 대화창 | 초상화 + 화자 이름 + 대사 | 허브 NPC, 보스 진입 |
| 하단 자막 | 한 줄, 2초 표시 후 페이드 | 전투 바크 (파츠 파괴, 보스 전투 중) |
| 말풍선 | 머리 위 한 줄. 관중은 동시 최대 3개 | **관중, NPC 반응, 근접 혼잣말** |

### 2. 대사 줄 단위 연출 명령

| 연출 | 내용 |
|---|---|
| 확대 | 화자 또는 지정 위치로 카메라 확대 |
| 흔들림 | 화면 흔들림 (강도 지정) |
| 페이드 인/아웃 | 1초 |
| 사운드 | 효과음, BGM 전환 |
| 표정 | 초상화 표정 변경 |

1. 연출을 기다리는 시간에는 **최대 대기 시간**을 둔다 (8.g 대사 연출 대기 제한) [신규]

## xiii. 글자 사운드 [변경: 오타 수정]

1. 동물의 숲처럼 글자가 나올 때마다 소리가 난다
2. **화자별**로 다른 음색
3. 공백, 문장부호에서는 소리 없음

## xiv. 편의 기능

| 기능 | 동작 |
|---|---|
| 즉시 표시 | 글자가 나오는 중 클릭/확인 → 문장 즉시 완성 |
| 다음 대사 | 문장 완성 상태에서 클릭/확인 |
| 스킵 | 남은 대화 전체 건너뛰기. 안 읽은 대사가 있으면 확인 창 |
| 빨리감기 | 누르고 있는 동안 읽은 대사만 빠르게 진행 |
| 오토 | 문장 길이에 비례해 자동 진행 |
| 백로그 | 지나간 대사 다시 보기 (최근 200줄) |
| 재도전 축약 | 보스 재도전 시 진입 대사를 1줄로 축약 |

1. 스킵해도 스토리 진행(챕터 변경 등)은 정상 반영된다
2. 대화 시작 직후 0.25초, 줄마다 0.12초는 입력을 무시한다 (연타로 대사를 놓치는 것 방지)

## xv. 입력·시간·세이브

### 1. 입력 상태 분리

| 상태 | 사용 키 | 비고 |
|---|---|---|
| 필드 | 4방향 이동(WASD / 방향키), E 상호작용 | 고물 수집과 같은 키 |
| 전투 | ←/→ 이동, ↑ 점프, Space 회피, D 기본기, Q/W/E/R 파츠 스킬 | 사이드뷰 |
| 대화 | Space / Enter / 좌클릭 확인, Esc 스킵, Ctrl(홀드) 빨리감기, Tab 오토, L 백로그 | |

1. 세 상태는 동시에 켜지지 않는다
   a. 대화 중 Space를 눌러도 회피가 나가지 않는다
2. 대화가 끝난 직후, 누르고 있던 키를 뗄 때까지 필드·전투 입력을 받지 않는다 (8.e 입력 전환 보호)

### 2. 시간 처리 [변경]

1. 대화창은 열릴 때 **UI 매니저의 열린 UI 스택에 등록**되고, 닫힐 때 빠진다
   a. 스택이 비어 있을 때만 인게임 시간이 진행된다 (6.a.v)
   b. 대화 시스템이 시간을 직접 멈추지 않는다
2. 보스 진입 대화 중에는 보스와 투사체도 멈춘다
3. 전투 바크, 비강제 말풍선은 UI 스택에 등록하지 않는다 (시간을 멈추지 않음)

### 3. 대사 트리거 평가와 이벤트 큐 [신규]

1. 00시 일 경계 처리의 **8번째(마지막) 순서**에서 대사 트리거를 평가한다 (8.e)
   a. 토벌 기록 확정, 랭커 점수 갱신, 시즌 판정, 포상, 고철 리필, 경매 정산이 모두 끝난 뒤의 값으로 판정한다
   b. 예: 경매 정산 결과(유찰) → 경매장 NPC 반응 말풍선 준비, 순위 구간 변경 → 서사 이벤트 준비
2. 전투, 대화, UI 사용 중 발생한 대사 이벤트는 **이벤트 큐**에 쌓았다가 필드 복귀 시 순서대로 출력한다
   a. 대화 중에 다른 대화가 끼어들지 않는다
   b. 순서: 메인 스토리(서사 이벤트) → 길드 연락 등 시스템 이벤트 → 반응 말풍선

### 4. 진행 기록과 세이브 [변경]

1. 저장 항목
   a. 대사별 재생 횟수
   b. 읽은 대사 줄 (빨리감기·스킵 판단용)
   c. 스토리 챕터 등 대사 전용 값
2. 대사는 순서 번호가 아닌 고유 ID로 기록한다
   a. 중간에 대사를 추가·삭제해도 기존 세이브의 기록이 어긋나지 않는다
3. 대사 ID를 바꿀 때는 이전 ID를 함께 적어 기록을 이어받는다
4. 대사 기록은 **게임 세이브와 같은 저장 1회**에 묶는다 (8.f, 8.c 보상 지급 원자성과 같은 원칙)
5. 세이브 파일은 **체크섬**으로 검증하고, 실패 시 백업 세이브를 불러온다 (8.b, 8.f)

## xvi. 데이터 관리

1. 파일 구성

| 파일 | 내용 |
|---|---|
| 변수 목록 | 조건에 쓸 수 있는 값, 타입, 기본값, 허용값 |
| 화자 목록 | 화자 ID, 이름, 표정 목록, 글자 사운드 |
| 대사 풀 | 노출 지점별 대사 묶음, 조건, 우선순위, 소비 규칙, 연출 |
| 문자열 테이블 | 실제 문장 (언어별) |

2. 자동 검사
   a. 대사 데이터를 저장하는 순간 오류를 검사한다
   b. 오타, 없는 변수, 잘못된 값, 절대 나올 수 없는 대사, 기본 대사 누락, **조건·연출 명령의 순환 참조** 등
   c. 오류가 있으면 빌드가 되지 않는다
3. 배포 [신규]
   a. 대사 JSON은 **빌드 시 패킹**한다 (8.b 데이터 패킹)
   b. 실행 중 로드에 실패하면 **기본 대사로 폴백**한다. 대화가 열리지 않아 진행이 막히는 일이 없게 한다
   c. 대사 테스트용 디버그 키는 **개발 빌드에서만** 포함한다 (8.b 디버그 기능 분리)

## xviii. 미정 사항

1. **대사 작성 방식** — JSON 직접 작성 vs 스프레드시트 작성 후 변환. 비교 후 결정 예정
2. **세이브 형식** — 추천안: **JSON + 체크섬** (아래). 팀 게임 세이브 형식과 함께 최종 결정
   a. 오프라인 싱글 게임이라 목표는 해킹 차단이 아니라 **손상·수정 감지** (8.a). 체크섬으로 충분하다
   b. 개발 중 세이브를 메모장으로 바로 열어 확인할 수 있다
   c. C#의 대표적인 바이너리 직렬화 도구(BinaryFormatter)는 Microsoft가 보안 문제로 사용 중단을 권고했다. 바이너리로 가면 직접 형식을 만들어야 해서 비용이 크다
   d. 배포 빌드에서 "읽기 어렵게" 하고 싶다면 저장 직전 압축만 추가하면 된다 (형식은 그대로 JSON)
