## 0. 작업 방식 — 씬 자동 배치 메뉴

### 0-1. 무엇이 바뀌었나

| 이전 | 지금 |
|---|---|
| 스크립트 작성 후 오브젝트 생성·스크립트 부착·인스펙터 연결을 손으로 | Unity 메뉴 `Tools > Dialogue > (단계) 배치` 한 번으로 자동. **위치·크기만 손으로 다듬는다** |

- 비유: 미리 조립된 완성품(프리팹)을 불러오는 것이 아니라, **조립 설명서(에디터 스크립트)대로 지금 씬에 맞춰 조립**한다

### 0-2. 안전장치

| 장치 | 내용 |
|---|---|
| 실행 범위 | 열린 씬이 `Assets/LHM/` 안에 있을 때만 실행. 다른 팀원 씬에서는 경고만 띄우고 아무것도 하지 않는다 |
| 되돌리기 | `Undo`에 묶여 있어 **Ctrl+Z 한 번**으로 그 단계 배치 전체가 사라진다 |
| 자동 저장 안 함 | 결과를 보고 직접 Ctrl+S |
| 중복 방지 | 이미 배치된 것은 건너뛴다. 두 번 눌러도 중복 생성되지 않는다 |
| 빌드 제외 | `Editor` 폴더 안에 있어 게임 빌드에 들어가지 않는다 |
| 기존 오브젝트 | 지우지 않는다. 겹치는 기능은 **비활성화만** 한다 (예: `Step06_DialogueTest`) |

### 0-4. 코드 요점

| 코드 | 설명 |
|---|---|
| `[MenuItem("Tools/Dialogue/...")]` | Unity 상단 메뉴에 항목을 만든다 |
| `Undo.RegisterCreatedObjectUndo` / `Undo.AddComponent` / `Undo.RecordObject` | 만든 것·바꾼 것을 Ctrl+Z 대상으로 등록 |
| `new SerializedObject(컴포넌트).FindProperty("칸 이름")` | `[SerializeField] private` 칸을 코드에서 채운다. 인스펙터에서 손으로 넣은 것과 똑같이 씬에 저장된다 |

## 10-1. UI 스택 등록

### 10-1-1. 목표

| 항목 | 내용 |
|---|---|
| 만드는 것 | 대화창·선택지가 열리면 "열린 UI 목록(UI 스택)"에 등록, 닫히면 해제. **스택이 비어 있을 때만 인게임 시계 진행** |
| 근거 | 기획서 xv.2 시간 처리 — 대화 시스템은 시간을 직접 멈추지 않는다 |
| 완료 조건 | 선택지·대화·상점이 열려 있는 동안 시계 정지, 모두 닫히면 다시 진행 |
| 새 스크립트 | `IUiStack.cs`, `DummyUiStack.cs` |
| 바뀐 스크립트 | `DialogueBox` (열기·닫기 2줄), `NpcChoiceMenu` (열기·종료 2줄) |

### 10-1-2. 왜 인터페이스 + 더미인가

- 팀 공용 UI 매니저가 아직 없다 (2026-10-31 확인)
- KDU 폴더의 `IGameClock` + `DummyGameClock`과 같은 방식: **약속(인터페이스)만 정해 두고 임시 구현으로 진행**
- 나중에 팀 UI 매니저가 `IUiStack`을 구현하고 `UiStack.Current = this`로 등록하면, 대화 시스템 코드는 바꾸지 않아도 된다

### 10-1-3. 스크립트 설명

| 코드 | 설명 |
|---|---|
| `IUiStack` | `Count`, `Push(ui)`, `Remove(ui)` 세 가지만 약속 |
| `UiStack.Current` | 지금 쓰는 UI 스택. 없으면(`null`) `Push`/`Remove`가 아무 일도 하지 않는다 |
| `DummyUiStack` | 열린 UI 목록 + 테스트 시계(08:00 시작, 1초에 10분). 목록이 비었을 때만 시계 진행. 화면 오른쪽 위 `ClockText`에 표시, 정지 중이면 "정지" |
| `Remove`가 `Pop`이 아닌 이유 | 열린 순서와 닫히는 순서가 다를 수 있다 (선택지 → 대화 → 대화 닫힘 → 선택지 종료). 맨 위만 빼는 대신 해당 UI를 찾아 뺀다 |
| 중복 등록 방지 | 같은 UI를 두 번 `Push`해도 한 번만 들어간다 |

- 전투 바크·말풍선은 스택에 등록하지 않는다 (시간을 멈추지 않음, 기획서 xv.2.3) — 14·15단계에서 지킬 것

## 10-2. 입력 3상태 분리

### 10-2-1. 목표

| 항목 | 내용 |
|---|---|
| 만드는 것 | 필드 / 전투 / 대화 입력 묶음 중 **하나만 켜지게** 한다. 대화가 끝난 직후에는 **누르고 있던 키를 뗄 때까지** 필드·전투 입력을 받지 않는다 |
| 근거 | 기획서 xv.1 입력 상태 분리, 8.e 입력 전환 보호 |
| 완료 조건 | 대화 중 이동·회피 안 됨, 마지막 Space가 회피로 이어지지 않음 |
| 새 파일 | `03.Data/Input/RealSteelInput.inputactions`, `InputModeController.cs`, `Step10_InputTest.cs` |
| 바뀐 스크립트 | `DialogueBox`, `NpcChoiceMenu`, `PlayerInteractor`, `Step09_TestMover` — 키보드 직접 읽기 → 컨트롤러 경유 |

### 10-2-2. 입력 파일

공용 `Assets/InputSystem_Actions.inputactions`는 **수정하지 않는다** (LHM 밖, 팀 공용). LHM 전용 파일을 따로 둔다.

| 맵 | 액션 | 키 |
|---|---|---|
| Field | Move | WASD / 방향키 |
| | Interact | E |
| Battle | Move | ← / → |
| | Jump / Dodge / Basic | ↑ / Space / D |
| | PartQ / PartW / PartE / PartR | Q / W / E / R |
| Dialogue | Confirm | Space, Enter, 좌클릭 |
| | Up / Down | W·↑ / S·↓ (선택지 이동) |
| | Select | E, Space, Enter (선택지 결정) |
| | Cancel | Esc (선택지 나가기, 상점 닫기) |
| | Skip / FastForward / Auto / Backlog | Esc / Ctrl / Tab / L — **12·13단계에서 사용 예정** |

### 10-2-3. 스크립트 설명 — `InputModeController`

| 코드 | 설명 |
|---|---|
| 상태 결정 | `UiStack.Current.Count > 0`이면 **Dialogue**, 아니면 기본 상태(`baseMode`: Field 또는 Battle) |
| `Apply` | 세 맵을 모두 끈 뒤 지금 상태의 맵만 켠다 |
| 입력 전환 보호 | Dialogue에서 빠져나올 때 키가 눌려 있으면 맵을 켜지 않고 기다린다(`IsWaitingRelease`). 모든 키·마우스 버튼을 떼면 그때 켠다 |
| `[DefaultExecutionOrder(-100)]` | 다른 스크립트보다 먼저 실행해, 같은 프레임 안에서 상태가 먼저 정해지게 한다 |
| `WasPressed / IsPressed / Read<T>(맵, 액션)` | 꺼진 맵의 액션은 항상 "안 눌림". 그래서 대화 중 필드 이동이 자동으로 막힌다 |
| `SetBaseMode` | 게임(전투 진입·종료)이 Field ↔ Battle을 바꿀 때 부른다. Dialogue로는 바꿀 수 없다 (UI 스택이 정함) |
| 버튼 액션 `initialStateCheck: false` | 맵이 켜지는 순간 이미 눌려 있던 키는 "방금 눌림"으로 치지 않는다. 선택지를 연 E가 바로 선택으로 이어지지 않는 이유 |
| UI 스택이 없을 때 | 노란 경고. 대화 상태로 바꿀 수 없으므로 10-1이 먼저 필요 |

- 컨트롤러가 없는 씬(예전 테스트 씬)에서는 각 스크립트가 **예전처럼 키보드를 직접 읽는다** (대체 경로)
- `Step09_DialogueDebug`의 F키, `Step10_InputTest`의 `` ` `` 키는 디버그라 키보드를 직접 읽는다 (개발 빌드 전용)

## 11. 보스 토벌 진입

### 11-1. 목표

| 항목 | 내용 |
|---|---|
| 만드는 것 | 보스 토벌 진입 시 대사 → 끝나면 전투 시작. 재도전은 1줄, 3패 후 첫 진입에 기믹 힌트 1회, 난이도별 분기 |
| 근거 | 기획서 iv 보스 토벌 진입, xiv 재도전 축약, xvii.2 보스 재도전 |
| 새 파일 | `boss_entry.json`, `BossEntryDialogue.cs`, `Step11_BossEntryTest.cs` |
| 바뀐 파일 | `variables.json`(변수 3개), `strings_ko.json`(문장 11개 + `speaker.wheel`), `Step09_DialogueDebug`(`SelectedDifficulty`, `RecordHunt` 공개) |
| 메인 스토리 트리거 | 서사 이벤트는 00시 평가 → 이벤트 큐를 거쳐 나오므로 **11-2단계로 이동** |

### 11-2. 새 변수

| 변수 | 타입 | 누가 채우나 | 쓰임 |
|---|---|---|---|
| `hunt.targetBoss` | string | 전투 진입 직전, 게임(지금은 테스트 스크립트) | 들어갈 보스 |
| `hunt.targetDifficulty` | enum (none ~ hell) | 같음 | 난이도별 진입 대사 |
| `hunt.bossAttemptCount` | int | 전투 시작 시 +1 | 첫 도전(0) / 재도전 구분 |

- 기존 `hunt.bossLoseCount`(시즌 보스에게 진 횟수, 보스 기준)를 힌트 조건에 그대로 쓴다
- 대사는 변수를 **읽기만** 한다 (기획서 x.2). 값을 바꾸는 것은 게임 쪽이다

### 11-3. 대사 데이터 (`boss_entry.json`)

| id | band | 소비 | 조건 | 줄 수 |
|---|---|---|---|---|
| `boss_entry_hint` | Critical | 1회 | `bossLoseCount >= 3` | 3 |
| `boss_entry_first` | Story | 1회 | `bossAttemptCount == 0` | 3 (길드 안내 → 보스 → 주인공) |
| `boss_entry_first_hell` | Story | 1회 | 위 + `targetDifficulty == hell` | 3 |
| `boss_entry_retry` | Fallback | 제한 없음 | 없음 (기본 대사 의무) | 1 |
| `boss_entry_retry_hell` | Fallback | 제한 없음 | `targetDifficulty == hell` | 1 |

**코드 없이 데이터 규칙으로 동작하는 이유** (4·5단계 규칙)

| 상황 | 선택 결과 | 규칙 |
|---|---|---|
| 첫 도전 | `first` (Story > Fallback) | 단계 우선 |
| 첫 도전, 헬 | `first_hell` (조건 2개 > 1개) | 같은 단계면 조건이 더 구체적인 쪽 |
| 재도전 | `retry` — `first`는 `bossAttemptCount == 0`이 아니라서 탈락 | 조건 |
| 3패 후 첫 진입 | `hint` (Critical) | 단계 우선 |
| 그 다음 진입 | `retry` — `hint`는 1회 소비됨 | maxPlays 1 |

### 11-4. 스크립트 설명

#### `BossEntryDialogue` (실제 게임용)

| 코드 | 설명 |
|---|---|
| `Play(Action onFinished)` | `manager.Talk("boss_entry")`로 진입 대사를 열고, 대화창 `Closed` 이벤트에서 `onFinished`(전투 시작)를 부른다 |
| 재생 실패 시 | 노란 경고 후 **바로 `onFinished`** — 대사 문제로 전투 진입이 막히지 않게 (기획서 xvi.3 폴백 원칙) |
| `IsPlaying` | 진입 대사 재생 중 여부. 중복 호출 방지 |
| `OnDestroy` | 이벤트 구독 해제 (씬 전환 시 끊긴 참조 방지) |

전투 담당자 연동 방법:

```
1. variables.Set("hunt.targetBoss", 보스ID)
2. variables.Set("hunt.targetDifficulty", 난이도)
3. bossEntry.Play(전투시작함수)
4. 전투 시작 시: hunt.bossAttemptCount +1, InputModeController.SetBaseMode(Battle)
5. 전투 종료 시: hunt.lastResult / lastBoss / lastDifficulty / count / winCount·loseCount / bossLoseCount 기록, SetBaseMode(Field)
```

- 기획서 "보스 진입 대화 중 보스·투사체도 멈춤"은 전투 쪽이 `UiStack.Current.Count > 0`일 때 멈추는 방식으로 맞춘다
