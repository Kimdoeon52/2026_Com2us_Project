# RSBillboard — 2.5D 스프라이트 빌보드 (URP)

3D 씬 안에 픽셀 스프라이트를 세운다. HD-2D 카메라(낮은 FOV + 내려다보는 피치) 전제.

```
Assets/RSBillboard/
    BillboardPixelLit.shader      ← Editor 폴더 밖
    SpriteFlash.cs                ← 피격 플래시 (런타임)
```

---

## 설계 결정 세 개

이 셰이더에서 진짜 중요한 건 옵션이 아니라 이 세 가지 판단이다.

### 1. Y축 빌보드 + 부분 기울기

| 방식 | 문제 |
|---|---|
| 완전 빌보드 (카메라 정면) | 카메라가 내려다보면 스프라이트도 같이 누워서 **발이 바닥에서 뜬다** |
| Y축만 회전 | 발은 붙지만 피치 34°만큼 **눌려 보인다** (키가 작아짐) |
| **부분 기울기** | 둘의 절충. 옥토패스도 캐릭터를 살짝 뒤로 젖혀 둔다 |

`카메라 기울기 따라가기` 기본 **0.35**. 네 카메라 피치가 34°라 이 정도면 키는 거의 복원되고 발은 안 뜬다. 발이 뜨는 게 보이면 낮추고, 키가 눌려 보이면 올려라.

### 2. 알파 블렌딩이 아니라 오려내기

반투명으로 그리면 두 가지가 깨진다.

- **3D 지오메트리와 정렬이 뒤집힌다** — 건물 뒤에 있어야 할 캐릭터가 앞에 그려짐
- **깊이 버퍼에 안 써져서 DOF가 캐릭터를 무시한다** — 배경만 흐려지고 캐릭터는 혼자 선명

픽셀아트는 경계가 어차피 딱 떨어지니까 오려내기가 맞고, 그러면 **정렬이 3D 오브젝트와 완전히 동일하게** 동작한다. 불투명 큐 + ZWrite On + `DepthOnly` 패스까지 넣어 뒀다.

### 3. 조명을 색조로만 받는다

스프라이트에는 **이미 명암이 그려져 있다.** 거기에 조명을 100% 곱하면 원화가 망가진다.

`조명 반영` 기본 **0.7** — 원본 색과 조명 받은 색 사이를 고른다.

```
0     원본 그림 그대로. 씬에서 붕 뜬다
0.7   씬의 분위기색을 입지만 원화가 살아 있다
1     완전히 조명대로. 어두운 곳에서 그림이 안 보인다
```

**0이 아니어야 하는 이유는 그림자다.** 캐릭터가 처마 밑이나 건물 그늘에 들어가면 어두워지는데, 그게 캐릭터를 씬에 붙여 놓는 가장 큰 요소야.

`법선 기울이기`는 조명을 어느 방향으로 받을지다. 0이면 카메라쪽(균일해서 픽셀아트에 유리), 1이면 하늘쪽(바닥과 같은 빛을 받아 더 잘 녹는다). 기본 0.5.

## 피격 플래시

경직이 없는 전투 설계라 **"맞았다"는 신호를 연출이 혼자 져야 한다.** 그중 제일 값싸고 확실한 게 흰색 한 프레임이다.

`SpriteFlash` 를 캐릭터에 붙이고 피격 시점에 호출하면 된다.

```csharp
GetComponent<SpriteFlash>().Flash();

// 세기를 다르게: 약공격은 약하게, 필살기는 세게
flash.Flash(0.12f, 1f, Color.white);
```

머티리얼을 복제하지 않고 `MaterialPropertyBlock` 으로 넣으므로 **같은 머티리얼을 쓰는 두 캐릭터가 같이 번쩍이지 않는다.**

켜질 때는 즉시, 꺼질 때는 완만하게 — 타격 순간이 더 또렷하게 읽힌다.

## 외곽선 (기본 꺼짐)

배경이 복잡해지면 캐릭터가 묻힌다. 1텍셀 외곽선이 그걸 막는다.

> **스프라이트 시트를 자른 프레임에는 주의.** 이웃 텍셀을 읽는 방식이라
> 프레임 사이에 여백이 없으면 **옆 프레임 그림을 끌어온다.**
> 프레임마다 투명 여백이 2px 이상 있을 때만 켜라.

한 프레임 = 한 파일이면 문제없다.

## 렌더러는 SpriteRenderer 보다 쿼드 MeshRenderer 가 낫다

둘 다 동작하지만 URP에서 `SpriteRenderer` 는 그림자·깊이 패스 취급이 일관되지 않다. **DOF와 그림자를 제대로 받으려면** 쿼드 메시에 `MeshRenderer` 를 쓰고 텍스처를 프레임마다 갈아 끼우는 쪽이 안전하다.

이미 `SpriteRenderer` 로 돌아가고 있다면 먼저 그대로 써 보고, 그림자가 안 지거나 DOF가 캐릭터를 무시하면 그때 쿼드로 바꿔라.

**피벗이 발밑에 있어야 한다.** 빌보드가 피벗을 축으로 도니까, 피벗이 가운데면 회전할 때 발이 미끄러진다.

## 텍스처 임포트

```
Filter Mode      Point
Compression      None
Mipmaps          끄기
NPOT Scale       None
Wrap Mode        Clamp      ← 스프라이트는 Repeat 가 아니라 Clamp
```

타일 텍스처와 달리 스프라이트는 **Clamp** 다. Repeat 로 두면 외곽선이 반대쪽 끝을 물어온다.

## 좌우가 뒤집혀 보이면

`좌우 반전` 토글을 켜라. 쿼드 메시의 정점 방향에 따라 갈리는 부분이라 프로젝트마다 다를 수 있다. `RobotActor` 쪽에서 이미 flipX 를 쓰고 있으면 둘 중 하나만 써야 한다 — 둘 다 켜면 상쇄된다.

## 검증 상태

**Unity에서 컴파일해 보지 않았다.** 에러가 나면 줄 번호와 함께 알려줄 것.
빌보드 방향(좌우 반전 · 기울기 부호)은 눈으로 봐야 확정되는 부분이라 위 토글로 맞추면 된다.
