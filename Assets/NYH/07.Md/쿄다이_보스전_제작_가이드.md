# 쿄다이 보스전 제작 가이드

> **문서 목적:** 지역 2 보스 '쿄다이'의 보스전 구성과
> 시각·애니메이션·이펙트·UI 제작 항목을 한 문서로 정리한다.\
> **구성:** 총 12페이지를 기준으로 제작 문서를 나누어 작성할 수 있도록
> 구성했다. 여기서 '페이지'는 원본 기획서의 페이지 번호가 아니라, 제작용
> 문서의 권장 섹션이다.

## 2026-10-30 조정 — 지금 모델·구조에 맞춘 범위

현재 쿄다이 모델(리깅된 두 발 메카, Tarvos+Mech_rigged)과 게임 구조(2D 횡스크롤 경기장,
원근 메인 카메라, 경기장 뒤에 선 3D 모델 + ProPixelizer 픽셀화)로는 구현이 어렵거나
연출이 맞지 않는 항목을 **본문에서 빼서 맨 아래 「구현 제외 항목」에 이유와 함께 모았다.**

**가져가는 핵심**

1.  **해킹(검수 시선)** — 탐조등에 노출되면 해킹 게이지가 차고, 가득 차면 타깃 파츠 강제 회수·스킬 봉인
2.  **레드 록온(빨간 조준선 → 레이저)** — 냉각탑 유도 파괴 포함
3.  **팔 위주 공격** — 배경 → 전이 → 공격 → 잔류 → 복귀 레이어 규칙을 팔로 보여준다

**제작 방식:** 패턴은 담당자(남윤호)가 Unity 애니메이션 창에서 직접 만든 온몸
애니메이션을 기준으로 짠다. 애니메이션 → 모션 창(손 키·레이어 띠·판정 이벤트) →
`KyodaiMotionPattern` 순서. 아래 패턴 흐름은 원본 기획 기준이고, 실제 동작 모양과
타이밍은 애니메이션을 만들면서 확정한다(원본 기획서에 있는 수치는 그대로 지킨다).

## 문서 읽는 법

각 섹션은 다음 항목으로 구성한다.

-   **필요 오브젝트:** 화면과 게임 월드에 배치할 모델 및 요소
-   **필요 애니메이션:** 오브젝트의 움직임과 상태 변화
-   **필요 이펙트:** 공격·피격·환경 효과
-   **필요 UI:** 플레이어에게 전달할 정보
-   **필요 이미지:** 제작자 간 시각적 기준을 맞추기 위한 콘셉트·상태
    비교 이미지

원본 기획서에 명시된 내용과 제작을 위해 추가로 제안하는 항목을 구분한다.
구체적인 외형, 연출 타이밍, 수치가 원본에 없는 경우에는 확정 사항으로
취급하지 않는다. **(제안)** 표시는 원본에 없는 항목이다.

# 01. 보스 전체 콘셉트 및 실루엣

## 목적

쿄다이의 전체 형태와 경기장 내 배치, 신체 부위의 구조 및 크기 관계를
정의한다. 쿄다이는 경기장 전체를 공격 범위로 사용하는 거대 기계
보스이며, **팔**이 배경과 전경을 오가며 전투에 개입한다. 다리는 몸을 받치는
배경 요소로만 쓴다(→ 구현 제외 항목 1).

## 필요한 오브젝트

| 오브젝트 | 세부 구성 |
|---|---|
| 보스 본체 | 머리, 몸통, 왼팔, 오른팔, 왼다리, 오른다리 (다리는 배경 전용) |
| 메인 렌즈 | 머리의 렌즈 — 탐조등·레드 록온의 발사 지점 |
| 관절 | 어깨, 팔꿈치, 손목 (팔 공격에 쓰는 관절) |

## 필요한 애니메이션

-   배경에서 좌우로 움직이는 대기 애니메이션
-   머리와 렌즈가 플레이어를 추적하는 움직임 (머리 뼈 위치 수정 필요 — 현재 사람 목 위치에 있음)
-   양팔의 대기 움직임
-   몸체가 좌우로 이동할 때의 무게감 있는 움직임

## 필요한 이미지

1.  보스 전체 정면 실루엣
2.  보스 전체 측면 실루엣
3.  머리 및 메인 렌즈 확대 이미지
4.  팔의 개별 이미지
5.  보스와 플레이어의 크기 비교 이미지

**제작 체크:** 보스의 크기와 플레이어의 크기 차이, 팔이 경기장으로 진입할 수
있는 구조가 한눈에 보여야 한다.

# 02. 레이어 및 판정 구조

## 목적

쿄다이 보스전의 핵심 시스템이다. 보스의 팔이 배경에서 전경으로 이동해
공격하고, 공격이 끝난 뒤 잔류하는 동안 플레이어가 해당 부위를 공격할 수
있게 한다.

## 레이어 상태 정의

| 상태 | 위치 및 동작 | 보스에게 피격 | 보스를 타격 | 시각 표시 |
|---|---|---|---|---|
| 배경 | 본체 전체 및 대기 중인 팔 | 불가 | 불가 | 어둡고 저채도 |
| 전이 | 배경에서 전경으로 진입 | 불가 | 불가 | 크기 확대 및 그림자 생성 |
| 전경·공격 | 휘두르기·찍기 진행 중 | 가능 | 불가 | 붉은 테두리 |
| 전경·잔류 | 공격 후 박히거나 정지 | 불가 | 가능 | 흰 테두리, 피격 시 금속 이펙트 |
| 복귀 | 전경에서 배경으로 빠지는 중 | 불가 | 불가 | 다시 어두워짐 |

## 필요한 오브젝트 및 기능

-   배경용 보스 부위 표현
-   전경용 보스 부위 표현
-   전경 진입 시 크기 및 위치 변화 (원근 카메라라 앞으로 나오면 자연히 커진다)
-   그림자 예고 표현
-   상태에 따른 테두리 및 명도 변화 (테두리는 ProPixelizer 외곽선 색을 부위별로 바꿔서)
-   상태별 충돌·피격 판정 전환

## 필요한 애니메이션

1.  배경 → 전경 전이
2.  전경 공격
3.  공격 종료 후 잔류
4.  전경 → 배경 복귀

## 필요한 이펙트

-   전이 시 크기 확대
-   전이 시 바닥 그림자
-   공격 중 붉은 테두리
-   잔류 중 흰 테두리
-   타격 시 금속 파편 및 스파크
-   복귀 시 어두워지는 효과

## 필요한 이미지

-   동일한 팔을 기준으로 한 5가지 상태 비교 시트
-   상태별 충돌 판정 범위
-   공격 중과 잔류 중의 플레이어 대응 차이

**제작 체크:** 팔 하나를 기준으로 배경 → 전이 → 공격 → 잔류 → 복귀까지
구현한 프로토타입을 먼저 검증한다.

# 03. 검수 시선 및 해킹 시스템 ★ 핵심 기믹

## 목적

렌즈의 빛 안에 머무르면 해킹 게이지가 차고, 게이지가 가득 차면 현재
타깃으로 지정된 플레이어 파츠의 내구도가 감소하고 스킬이 봉인된다.
시선은 숨는 방식이 아니라 달려서 따돌리는 위협으로 설계되어 있다.

## 필요한 오브젝트

-   메인 렌즈
-   렌즈에서 투사되는 탐조등 (바닥에 닿는 빛 — 2D로 표현)
-   플레이어를 추적하는 레이저 조준선

## 타깃 지정

| 타깃 파츠 |
|---|
| 왼팔(Q) |
| 오른팔(W) |
| 왼다리(E) |
| 오른다리(R) |

패턴 시작 시 HUD의 해당 파츠 아이콘에 테두리가 표시된다. 머리 파츠는 타깃에서
제외한다. 원본의 "서브 렌즈 점등"은 모델에 서브 렌즈가 없어 뺐다(→ 구현 제외 항목 2).
**(제안)** 타깃 파츠 색으로 메인 렌즈 빛 색을 바꿔 HUD와 맞춘다.

## 원본 기획서의 수치

| 항목 | 값 |
|---|---|
| 빛 노출 시 게이지 상승 | +40/초 |
| 빛 이탈 후 감소 시작 | 0.5초 지연 |
| 이탈 후 게이지 감소 | -30/초 |
| 회피(Space) 무적 중 | 게이지 상승 정지 |
| 강제 회수 | 타깃 부위 내구도 -1 |
| 스킬 봉인 | 4초 |
| 약 2.5초 노출 | 게이지 최대 도달 기준 |

## 필요한 애니메이션 및 상태 변화

1.  렌즈 점등
2.  탐조등이 플레이어 추적
3.  타깃 변경 시 HUD 테두리 이동
4.  해킹 게이지 최대 도달 시 렌즈 강한 발광
5.  파츠 강제 회수 연출

## 필요한 이펙트

-   렌즈 점등
-   탐조등 빔
-   해킹 진행 피드백
-   해킹 완료 경고
-   파츠 내구도 감소 이펙트

## 필요한 UI

-   Q/W/E/R 파츠 아이콘
-   현재 타깃 파츠 테두리
-   해킹 게이지
-   파츠 강제 회수 경고
-   스킬 봉인 표시

## 필요한 이미지

-   왼팔·오른팔·왼다리·오른다리 각각 타깃 지정 상태
-   해킹 게이지 0%, 50%, 100% 비교
-   파츠 강제 회수 전후 UI

# 04. 경기장 및 기물 배치

## 목적

보스의 공격과 플레이어의 대응에 사용되는 경기장 구조를 정의한다.
냉각탑은 레드 록온 레이저를 유도해 파괴한다. 원본의 중계 안테나는 뺐다(→ 구현 제외 항목 3).

## 필요한 배경 오브젝트

| 오브젝트 | 역할 및 구성 |
|---|---|
| 경기장 | 플레이어 이동 및 전투 공간 |
| 냉각탑 L/R | 레드 록온 레이저를 유도해 파괴하는 대상 |
| 천장 | 낙하물 발생 위치 |
| 바닥 | 충격파, 그림자, 플라즈마 표현 공간 |

## 냉각탑 제작 항목

-   냉각탑 기본 모델
-   레이저 피격 부위
-   피격 및 파손 단계
-   폭발 이펙트
-   파괴 후 잔해

### 냉각탑 파괴 효과

-   1개 파괴: 보스 과열 다운, 양팔이 전경에 4초 잔류
-   2개 모두 파괴: 2페이즈 전환

## 필요한 이미지

1.  경기장 전체 정면도
2.  경기장 전체 측면도
3.  냉각탑 파괴 전후 비교
4.  낙하물 발생 위치가 표시된 천장 이미지

# 05. 페이즈 1 패턴

**페이즈 목표:** 플레이어가 보스의 레이어 규칙, 공격 예고, 잔류 중 반격
구조를 학습하도록 한다.

## 5-1. 탐조등 추적 (해킹)

### 패턴 흐름

1.  렌즈 점등
2.  경고음
3.  빛이 플레이어를 추적
4.  플레이어가 달리거나 회피해 빛에서 이탈
5.  타깃 종료

### 필요한 리소스

-   렌즈 점등 애니메이션
-   탐조등 빔
-   플레이어 추적에 맞춘 빛 이동
-   경고음 및 타깃 표시
-   해킹 게이지 UI

원본 설명상 탐조등은 걷기보다 빠르고 달리기보다 느리다. 벽에 몰리면
회피로 빛을 관통해 탈출할 수 있다.

## 5-2. 레드 록온(유도형)

### 패턴 흐름

1.  조준선 생성
2.  조준선이 플레이어를 추적
3.  2초 동안 조준선이 좁아짐
4.  확정 조준 레이저 발사
5.  플레이어가 냉각탑으로 유도
6.  냉각탑 피격 및 파괴

### 필요한 리소스

-   조준 레이저
-   플레이어 추적 조준선
-   조준선 수축 애니메이션
-   확정 조준 경고
-   레이저 발사 이펙트
-   냉각탑 관통 및 파괴 이펙트

## 5-3. 팔 공격 (애니메이션 기준으로 확정)

원본의 진격 밟기(다리)와 손가락 5연타는 뺐다(→ 구현 제외 항목 1, 5). 1페이즈의
"레이어 규칙 학습" 역할은 팔 공격이 맡는다. 동작은 담당자가 만든 애니메이션으로
확정한다(예: 현재 제작 중인 내려찍기 `Boss2_leftArm`).

### 필요한 리소스

-   팔 전경 진입 · 공격 · 잔류 · 복귀 애니메이션
-   그림자 예고
-   타격 이펙트, 바닥 먼지
-   잔류 중 피격 판정

# 06. 페이즈 2 패턴

**페이즈 목표:** 양팔을 적극적으로 사용하고, 공격 범위와 동시 위협을 늘린다.
원본 설명에서는 과열에서 깨어난 보스가 배경에서 더 빠르게 좌우로 이동하며
팔을 번갈아 전경으로 내민다.

## 6-1. 충격파 내려치기

### 패턴 흐름

1.  주먹 그림자 0.8초 표시
2.  주먹이 바닥을 내려침
3.  충격파가 좌우로 퍼짐
4.  플레이어가 점프로 충격파를 넘음
5.  주먹 2초 잔류

### 필요한 리소스

-   왼팔 주먹 전경 진입
-   주먹 그림자 예고
-   주먹 내려찍기 애니메이션
-   좌우 충격파
-   바닥 균열
-   주먹 잔류 애니메이션

## 6-2. 손바닥 압착

### 패턴 흐름

1.  경기장 1/3을 덮는 그림자 표시
2.  1.2초 예고
3.  손바닥이 내려와 해당 구역을 압착
4.  손등이 3초간 잔류
5.  플레이어가 손등을 공격 (손등 위에 올라가는 것이 아니라 높이 있는 손등을 때리는 것으로 해석 — 확인 필요)

### 필요한 리소스

-   오른손 손바닥 전경 진입
-   넓은 손 그림자
-   손바닥 내려찍기
-   압착 충돌 이펙트
-   손등 잔류 애니메이션

## 6-3. 낙하물 + 스캔 (해킹)

### 패턴 흐름

1.  잔해 그림자 표시
2.  렌즈 점등
3.  천장에서 잔해가 떨어지는 동시에 시선이 플레이어를 훑음
4.  플레이어가 낙하물과 스캔을 동시에 회피

### 필요한 리소스

# 구현 제외 항목 (2026-10-30)

현재 모델과 게임 구조로 구현이 어렵거나 연출이 맞지 않아 본문에서 뺀 항목.
모델을 바꾸거나 해당 시스템을 새로 만들면 다시 넣을 수 있다.

## 1. 다리 공격 — 진격 밟기(원본 5-2), 걷어차기(원본 6-4), 다리 잔류·무력화

-   **안 되는 이유:** 현재 모델은 두 다리로 서 있는 메카다. 다리를 경기장 앞으로
    내밀면 몸을 받칠 다리가 없어 자세가 무너져 보인다. 걷어차기(경기장 아래를 수평으로
    쓸기)는 한 다리로 선 채 다른 다리를 옆으로 휘둘러야 해서 더 부자연스럽다.
    3회 내디딤은 본체가 앞으로 걸어 나와야 하는데, 몸이 가까워지면 경기장을 가린다.
-   **영향:** 다리 부위 피격(배율 0.8)·다리 무력화 UI 제외. 1페이즈 학습 패턴은 팔 공격이 맡는다.

## 2. 서브 렌즈 4개 (원본 01, 03)

-   **안 되는 이유:** 모델에 팔·다리별 서브 렌즈가 없다.
-   **영향:** 해킹 타깃 표시는 HUD 파츠 아이콘 테두리로만 한다. 해킹 시스템 자체는 그대로 유지.

## 3. 중계 안테나 (원본 04)

-   **안 되는 이유:** 높은 벽에 올라가 파괴하는 구조라 플랫포밍(벽·발판 오르기)이 필요한데,
    현재 경기장은 바닥 하나뿐이다. 파괴 효과(대응 서브 렌즈 소등 → 그 파츠 타깃 제외)도
    서브 렌즈가 없어 걸 데가 없다.
-   **영향:** 선택형 기믹이라 클리어에는 영향 없음.

## 4. 근접 검수 + 메인 렌즈 파괴 (원본 6-6, 07)

-   **안 되는 이유:** 메인 렌즈를 경기장 중앙으로 내미는 센서 촉수가 모델에 없다.
    렌즈 파손 단계 모델도 없다. 머리 뼈도 사람 목 위치에 잡혀 있어 렌즈 쪽을 따로 움직이기 어렵다.
-   **영향:** **2 → 3 페이즈 전환 조건이 비게 됨 — 기획 확정 필요.** 메인 렌즈 부위 배율(2.0) 피격 기회 없음.

## 5. 손가락 5연타 (원본 5-3)

-   **안 되는 이유:**
    -   손가락 뼈는 있지만 한 손의 손가락은 서로 붙어 있어서, 그림자 5곳을 순서대로 따로 칠 수 없다.
    -   픽셀화하면 손가락이 몇 도트라 구분이 잘 안 된다.
    -   "박힌 팔을 타고 올라가 높은 곳 공격"은 움직이는 3D 팔 위에 경사 발판 충돌이 필요하다. 현재 플레이어 이동은 바닥 높이 기준이다.
-   **영향:** 5-3 팔 공격으로 대체.

## 6. 3페이즈 기어오기 + 렌즈 잃은 보스 모델 (원본 08)

-   **안 되는 이유:** 두 발로 서는 메카가 엎드려 기어오는 온몸 애니메이션을 새로 만들어야 하고,
    파손 모델도 없다. 몸이 경기장 쪽으로 다가오면 화면을 가려 플레이어가 안 보인다.
-   **영향:** 3페이즈는 보스가 제자리에서 패턴(플라즈마·스캔·양팔 내려찍기)만 한다.

## 7. 양손 협공 (원본 6-1)

-   **안 되는 이유:**
    -   어깨가 화면 가운데 뒤에 있어서, 손을 화면 양 끝 바닥까지 보내려면 팔을 크게 늘려야 한다. 그러면 팔이 늘어나 보이고 팔꿈치가 뒤집힌다.
    -   "한쪽 손을 점프로 넘기"는 손이 길을 막는 단단한 충돌이 필요하다. 현재 보스 부위는 맞는 판정(통과 가능)만 있다.
-   **영향:** 2페이즈 동시 위협이 줄어든다. 애니메이션으로 손이 닿는 범위를 확인한 뒤 다시 설계하면 복귀할 수 있다.
