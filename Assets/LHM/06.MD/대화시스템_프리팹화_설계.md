## 1. 목표

| 항목 | 내용 |
|---|---|
| 만드는 것 | 대화 시스템과 NPC 상호작용을 **프리팹으로 만들어**, 새 씬에 드래그만 해도 동작하게 한다 |
| 완료 조건 | ① 빈 씬에 `DialogueSystem.prefab` + 플레이어 + NPC Variant를 놓고 **인스펙터 연결 없이** Play해서 9단계 점검표가 그대로 통과한다 ② NPC 종류를 늘릴 때 **코드를 고치지 않는다** |
| 하지 않는 것 | 새 기능 추가. 동작은 9단계와 같게 유지한다 |

## 2. 현재 구조에서 프리팹화를 막는 것

| # | 문제 | 위치 | 결과 |
|---|---|---|---|
| 1 | **프리팹 경계를 넘는 인스펙터 참조** | `PlayerInteractor` → `DialogueSystem`, `NpcMenu`, `InteractPrompt` / `NpcChoiceMenu` → `ShopPanel` | 프리팹 에셋은 씬 오브젝트를 참조할 수 없다. 씬에 놓을 때마다 칸을 다시 채워야 한다 |
| 2 | **선택지가 코드에 박혀 있음** | `NpcRole` enum + `NpcChoiceMenu`의 static 배열 | NPC 종류가 늘 때마다 코드 수정. Variant를 만들어도 바꿀 수 있는 게 없다 |
| 3 | **대화 시스템이 아닌 것이 섞임** | `ShopPanel`(상점), `Step09_*`(디버그), Director의 Main Camera 의존 | 프리팹에 넣으면 다른 시스템과 엉키고, 씬이 바뀌면 깨진다 |

## 3. 핵심 규칙

> **프리팹 안쪽 참조는 인스펙터로 연결하고, 프리팹 바깥은 코드로 찾는다.**

| 참조 | 방식 |
|---|---|
| DialogueBox → Voice / Portrait / Stage / Director | 같은 프리팹 안 → 인스펙터 |
| NpcChoiceMenu → MenuPanel / Title / OptionTemplate | 같은 프리팹 안 → 인스펙터 |
| PlayerInteractor → Manager / Menu / Prompt | 프리팹 바깥 → `DialogueManager.Instance` |
| NpcChoiceMenu → 상점·토벌 등 다른 시스템 | 프리팹 바깥 → `ActionChosen` 이벤트 |
| NPC → 대사 풀 · 화자 · 선택지 | 데이터 → `NpcDefinition` (ScriptableObject) |

## 4. 프리팹 구성

```
[A] DialogueSystem.prefab              게임 전체에 1개
 ├ DialogueSystem                      DialogueManager       ← 외부 창구
 ├ DialogueDirector                    DialogueDirector
 │  ├ Sfx                              AudioSource
 │  └ Bgm                              AudioSource
 └ DialogueCanvas                      Canvas (Overlay, Sort Order 100) + Canvas Scaler
    ├ FullscreenLayer                  CanvasGroup
    │ └ Background                     Image
    ├ IntermissionLayer                CanvasGroup
    │ ├ Tint / LetterboxTop / LetterboxBottom
    ├ FadeOverlay                      Image
    ├ InteractPrompt                   TMP Text + InteractPrompt (신규)
    ├ NpcMenu                          NpcChoiceMenu
    │ └ MenuPanel
    │    ├ Title
    │    └ OptionTemplate
    └ DialogueUI                       DialogueBox, AudioSource, DialogueVoice, DialoguePortrait, DialogueStage
       └ Box
          ├ Portrait / SpeakerName / BodyText

[B] NPC_Base.prefab                    NpcInteractable (Definition 칸)
 ├ Visual                              스프라이트 / 모델
 └ PromptAnchor                        이름표 위치 (빈 Transform)
     ↓ Variant
    NPC_Receptionist / NPC_JunkDealer / NPC_Auctioneer

[C] PlayerInteractor                   플레이어 프리팹에 컴포넌트로만 붙임. 연결 칸 0개

[데이터] NpcDefinition.asset           Assets/LHM/03.Data/Npc/
    npc_receptionist / npc_junkdealer / npc_auctioneer

[분리] DialogueDebug.prefab            Step09_DialogueDebug — 개발 씬에만
[분리] ShopPanel                        상점 시스템 소속으로 이전
[분리] EventSystem                      공용 UI 프리팹 (HUD·상점과 공유)
```

### 4-1. DialogueCanvas 자식 순서

프리팹 안에서 고정되므로 씬마다 깨질 일이 없다.
**FullscreenLayer → IntermissionLayer → FadeOverlay → InteractPrompt → NpcMenu → DialogueUI(맨 앞)**

### 4-2. 다른 캔버스와의 순서 (Sort Order 기준표)

| Sort Order | 캔버스 | 비고 |
|---|---|---|
| 0 | HUD | 체력, 인게임 시간 등 |
| 50 | 상점 · 토벌 신청 · 랭킹 보드 | 선택지에서 넘어가는 UI |
| **100** | **DialogueCanvas** | 대화는 항상 앞 |
| 200 | 일시정지 · 시스템 팝업 | 백로그를 일시정지 메뉴에서 열면 여기 (미정) |

## 5. `DialogueManager.Instance` — 외부 창구

### 동작

```
Awake
  Instance가 이미 있고 내가 아니면 → 내 루트 오브젝트 Destroy, return
  Instance = this
  (DontDestroyOnLoad 사용 시) DontDestroyOnLoad(루트)
  기존 로드 처리
OnDestroy
  Instance == this면 Instance = null
```

- 테스트하려고 씬마다 시스템 프리팹을 놓아 둬도 두 번째부터는 스스로 사라진다
- `Instance` 체크는 **Awake 첫 줄**에 둔다. 로드나 구독 뒤에 지우면 중복 로드 로그와 이벤트 중복 구독이 남는다

### Manager가 새로 노출할 것

| 멤버 | 설명 | 쓰는 곳 |
|---|---|---|
| `static Instance` | 창구 | PlayerInteractor, 이후 보스·00시 처리 |
| `Menu` | NpcChoiceMenu | PlayerInteractor |
| `Prompt` | InteractPrompt | PlayerInteractor |

## 6. `NpcDefinition` — 선택지 데이터화

### 구조

```
NpcDefinition (ScriptableObject)
  speakerId : string          "receptionist"
  poolId    : string          "guild_npc"
  actions   : NpcActionEntry[]

NpcActionEntry
  type      : NpcActionType   Talk / Exit / Shop / HuntApply / RankingBoard / RewardClaim
  labelKey  : string          "menu.talk"
```

| NpcDefinition | actions |
|---|---|
| `npc_receptionist` | HuntApply `menu.hunt_apply` / RankingBoard `menu.ranking_board` / RewardClaim `menu.reward_claim` / Talk `menu.talk` / Exit `menu.exit` |
| `npc_junkdealer` | Shop `menu.shop` / Talk `menu.talk_more` / Exit `menu.exit` |
| `npc_auctioneer` | Talk `menu.talk` / Exit `menu.exit` |

- `labelKey`를 따로 두는 이유: 같은 Talk라도 고물상만 "대화하기"다. 동작과 표시 문구를 분리한다
- `NpcRole` enum과 `NpcChoiceMenu`의 static 배열은 **삭제**한다

### 변경되는 것

| 대상 | 변경 |
|---|---|
| `NpcInteractable` | `role`, `poolId`, `speakerId` → `definition` 칸 하나. `promptOffset` → `promptAnchor` (Transform, 비우면 자기 위치) |
| `NpcChoiceMenu.Open` | `GetActions(role)` → `target.Definition.Actions` |
| 시작 시 검증 | Definition이 비었거나, poolId가 Manager에 없거나(`HasPool`), actions에 Exit이 없으면 에러 |

### Variant와 SO를 함께 쓰는 이유

| | Variant | NpcDefinition (SO) |
|---|---|---|
| 담는 것 | 외형, 크기, 상호작용 반경, 이름표 위치 | 대사 풀, 화자, 선택지 |
| 공유 | 프리팹 단위 | 여러 NPC가 같은 SO를 써도 됨 (지역마다 외형이 다른 접수원) |
| 수정하는 사람 | 아트 / 레벨 | 기획 — 프리팹을 열지 않는다 |

## 7. 선택지 처리의 위임 — `ActionChosen`

### 처리 분담

| type | 처리 |
|---|---|
| Talk | NpcChoiceMenu가 직접 → `manager.Talk(poolId)` |
| Exit | NpcChoiceMenu가 직접 → `End()` |
| 그 외 | `ActionChosen`으로 외부 시스템에 넘긴다 |

### 상태

```
Closed ──Open──▶ Menu ──Talk──▶ Talking ──대화창 닫힘──────────▶ Closed
                  │ ──Exit / Esc──────────────────────────────▶ Closed
                  │ ──그 외──▶ ActionChosen
                                 ├ 받아 준 시스템 있음 → Delegated ──EndInteraction()──▶ Closed
                                 └ 없음              → 즉시 Closed (경고 로그)
```

### 안전장치 — 받아 줄 시스템이 없을 때

- 위임만 하면, 상점 시스템이 아직 없을 때 상태가 `Busy`에 멈춰 **조작이 영원히 막힌다**
- 약속:
  1. 이벤트 인자에 `Handled` 표시를 둔다. 처리를 맡은 시스템은 `Handled = true`로 바꾼다
  2. 알림이 끝난 뒤 `Handled == false`면 메뉴가 즉시 `End()`한다 (지금의 "임시 로그 후 종료"가 이 동작이 된다)
  3. 처리를 맡은 시스템은 자기 UI가 닫힐 때 `menu.EndInteraction()`을 부른다
- `Delegated` 상태에서도 `IsBusy == true` → 이동·상호작용이 막힌다

### ShopPanel 분리

| 지금 | 분리 후 |
|---|---|
| `NpcChoiceMenu`의 `shopPanel` 칸, `HandleShopInput` | 둘 다 삭제 |
| 임시 상점 | `TempShop` 컴포넌트(상점 시스템 쪽)가 `ActionChosen`을 구독 → type이 Shop이면 열고 `Handled = true` → Esc/E로 닫을 때 `EndInteraction()` |

## 8. `PlayerInteractor`와 `InteractPrompt` 역할 분리

| | 지금 | 분리 후 |
|---|---|---|
| PlayerInteractor | 가장 가까운 NPC 찾기 + 이름표 위치 계산 + E 입력 | 가장 가까운 NPC 찾기 + E 입력. **UI를 모른다** |
| InteractPrompt (신규, 시스템 프리팹) | — | `Show(npc)` / `Hide()`. 월드 → 화면 좌표 변환, 카메라 뒤 숨김, 대상이 바뀔 때만 글자 갱신 |
| 연결 칸 | Manager, Menu, Prompt, World Camera | **없음** |

- 카메라는 `InteractPrompt`가 표시할 때마다 `Camera.main`을 조회한다 (9장 참고)
- 플레이어 프리팹은 대화 시스템이 없는 씬에서도 에러 없이 동작해야 한다 → `Instance == null`이면 아무것도 하지 않는다

## 9. 씬이 바뀌어도 유지할 때 (DontDestroyOnLoad)

> 10장 1번 답에 따라 필수 / 선택이 정해진다

| 항목 | 문제 | 대응 |
|---|---|---|
| Director의 Target Camera | 씬이 바뀌면 Main Camera가 바뀌어 캐시한 참조가 사라진다 | Awake 캐시 금지. **연출 시작 시마다** `Camera.main` 조회 |
| InteractPrompt의 카메라 | 위와 같음 | 위와 같음 |
| EventSystem | 씬마다 있으면 중복 경고 | 공용 UI 프리팹으로 분리 |
| `NpcInteractable.Active` | 씬 언로드 시 NPC가 남는가 | `OnDisable`에서 빠지므로 문제 없음 |
| 세이브 | — | 시스템이 하나로 유지되어 기록이 일관된다 |
| 개발 편의 | 아무 씬에서 Play | `RuntimeInitializeOnLoadMethod` + `Resources/DialogueSystem.prefab` 부트스트래퍼. `Instance`가 없을 때만 생성 |

## 10. 미정 사항 (구현 전 확인)

| # | 질문 | 영향 |
|---|---|---|
| 1 | **씬 구성** — 허브(경매장·길드·고물상)가 한 씬인가 여러 씬인가? 전투 씬에서도 보스 진입 대사·바크 때문에 시스템이 떠 있어야 하는가? | DontDestroyOnLoad 필수 여부. 전투 씬에서도 쓰면 `NpcMenu`·`InteractPrompt`를 필드에서만 켜지게 시스템 안에서 한 번 더 나눠야 한다 |
| 2 | **선택지가 상황에 따라 바뀌는가** — 받을 포상이 없으면 "포상 수령" 숨김/회색, 토너먼트 주간 전용 메뉴 등 | 그렇다면 `NpcActionEntry`에 `condition` 칸 추가, 기존 `DialogueConditions` 재사용. **SO 구조를 잡는 P1에서 함께 정해야** 데이터를 다시 만들지 않는다 |
| 3 | "대화" / 다른 시스템을 닫은 뒤 선택지로 돌아가는가 (9-17에서 이어짐) | `OnDialogueClosed`, `EndInteraction()` 동작 |
| 4 | 백로그를 일시정지 메뉴에서도 여는가 (작업기록 9장 7번) | Sort Order 200 캔버스 위치 |

## 11. 작업 순서

| 단계 | 내용 | 완료 확인 |
|---|---|---|
| P1 | `NpcDefinition` SO 생성, `NpcChoiceMenu` 데이터화, `NpcRole` 삭제. **씬은 그대로** | 9-5 B·C·E 점검 통과 |
| P2 | `DialogueManager.Instance` 추가, `InteractPrompt` 분리, `PlayerInteractor` 연결 칸 제거 | 9-5 B 통과, Player 인스펙터에 칸 없음 |
| P3 | `ActionChosen` + Handled 안전장치, `ShopPanel` → `TempShop` 분리 | 9-5 E 통과. `TempShop`을 꺼도 상점 선택 시 멈추지 않고 종료 |
| P4 | `DialogueSystem.prefab` 생성, `DialogueDebug.prefab` 분리 | **빈 씬**에 프리팹 드래그 + Play → 9-5 A·F 통과 |
| P5 | `NPC_Base` + Variant 3종 | 빈 씬에 Player·NPC Variant 놓고 9-5 전체 통과 |
| P6 | DontDestroyOnLoad, 부트스트래퍼, 카메라 지연 조회 | 씬 A → B 전환 후 대화·연출·세이브 정상, 시스템 1개 유지 |

- P1~P3은 프리팹 없이도 의미 있는 정리다. 여기까지 끝나면 P4~P5는 거의 드래그 작업이다
- P6은 실제 씬 전환이 생길 때 진행한다

## 12. 리스크 체크

| 리스크 | 증상 | 방어 |
|---|---|---|
| 시스템 프리팹 중복 | 대사 두 번 로드, 이벤트 두 번 실행 | Awake 첫 줄 Instance 체크 |
| 위임 후 응답 없음 | 선택지를 고르면 조작이 영원히 막힘 | Handled 안전장치 (7장) |
| 씬 전환 후 카메라 Missing | 연출 확대·흔들림 시 `MissingReferenceException` | 카메라 지연 조회 (9장) |
| Definition 누락 / 풀 ID 오타 | NPC에게 말을 걸면 아무 일도 없음 | 시작 시 검증 에러 (6장), 9-5 에러 시험 ④⑤ 유지 |
| 프리팹 Override 누적 | 씬마다 Variant 값이 달라져 원인 추적 곤란 | 역할 데이터는 SO에만 두고, 씬 Override는 위치만 허용 |
| 다른 UI와 겹침 | 상점이 대화창 위에 그려짐 | Sort Order 기준표 (4-2) |
